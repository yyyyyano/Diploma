# Безопасность и приватность

Почему так — ADR-0016, ADR-0010, ADR-0006; устройство — `docs/ARCHITECTURE.md` §6, §9.

- **Секреты** (ключи API, SMTP, токен бота) — через `platform/secrets`: AES-256-GCM, мастер-ключ `secrets/master.key`;
  поле только для записи (наружу — «задан ✓ / не задан»), приоритет «админка > env > умолчание»; не попадают в логи,
  ответы, трассы, ошибки, резервную копию ключа.
- **Логи** — ключ события + id из белого списка полей; никогда: email, ФИО, номера счетов и карт, телефоны, суммы с
  привязкой к пользователю, тексты переписки и документов, токены, cookie (OBS-04). Ошибки — через `scrub()`.
- **Локальный вход**: два слушателя — `local` (127.0.0.1:8140) и `lan` (8141, открывается переключателем в админке).
  Первый запуск, локальный почтовый ящик, демо-вход — middleware `localOnly` (признак — порт слушателя `local`, не IP
  и не `Host`); на сетевом слушателе этих маршрутов нет (R40, NFR-24).
- Каждый изменяющий запрос — проверка `Origin`/`Sec-Fetch-Site`; проверка `Host` (DNS-rebinding); cookie
  `kosht_session` (своё имя: cookie не различают порты localhost) `HttpOnly`, `SameSite=Lax`; без CORS, без
  `trustProxy`; CSP явный, без HSTS и `upgrade-insecure-requests` (ломают HTTP на localhost/LAN).
- **Ограничение частоты** (вход, сброс, код восстановления, ассистент) — ключ email/`user_id`, не `X-Forwarded-For`
  (в контейнере IP — адрес шлюза).
- **Пароли** ≥ 12 символов, argon2id (`node:crypto`, m = 64 МиБ, t = 3, p = 1), перехэш при входе; ссылки сброса
  одноразовые, 1 час;
  код восстановления — хэш, после использования выдаётся новый; сравнение секретов — постоянное по времени.
- **Админ** не видит финансов, профиля, фактов, переписки (PRIV-07): `admin` берёт данные только из admin-фасадов
  системных модулей; ссылку сброса пароля получает пользователь (R37); плагин `admin` Better Auth не подключать.
- **Блокировка** действует сразу (AUTH-11: сессии отзываются, `cookieCache` выключен); последнего админа нельзя удалить,
  заблокировать, лишить роли (AUTH-12).
- **Файлы** — тип по содержимому (`file-type`) + белый список + лимиты (ориентир: фото 15 МБ, выписка 25 МБ, до 10 за
  раз); путь `data/files/<householdId>/<fileId>` строит сервер; имя файла из запроса — только метаданные; выдача —
  после проверки владельца через `s`; разбор PDF/XLSX/HEIC — в `worker` с таймаутом и лимитом памяти, защита от ZIP-бомб.
- **Согласия** (PRIV-01/02/08) хранятся с версией текста и временем; отзыв облачного согласия действует на
  следующий же вызов модели; Telegram-привязка = отдельное согласие.
- **Удаление аккаунта** (PRIV-06) — через реестр владельцев данных: все `defineUserData`, файлы домохозяйства,
  трассы Langfuse, ожидающие задачи, привязка Telegram, затем запись `identity`. Подтверждение паролем.
- **Telegram** — только личные чаты; scope — только из `telegram_links`; код привязки одноразовый и короткоживущий.
- Ответ модели на сайте — санитизированный Markdown без HTML и картинок, ссылки — внутренние и pravo.by (SEC-05).

Правильно:

```ts
log.warn({ userId: s.scope.userId, code: "LOGIN_RATE_LIMITED" }, "auth.login.rate-limited");   // без email и IP-строки
```

Нельзя: `log.info("вход " + email)`; возвращать значение секрета в ответе; маршрут первого запуска без
`localOnly`; доверять `X-Forwarded-For`/`Host` для «это localhost»; `dangerouslySetInnerHTML` для ответа модели;
хранить пароль или код восстановления в открытом виде; ссылку сброса показывать админу, если есть почта или Telegram.
