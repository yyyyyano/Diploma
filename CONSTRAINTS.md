# Планка качества «Кошта»

Последний пересмотр: 2026-10-24 (оформлено вместе с архитектурой; кода ещё нет). Меняет только главная сессия и
только с согласия пользователя (раздел «Как менять планку»). **Прочитай перед кодом. Не ослабляй ради того, чтобы изменение прошло.**

Команды ниже появляются в бетонной фазе (`docs/ARCHITECTURE.md` §13); до неё действует только «Пол».
Числа с пометкой **[калибр.]** — разумные умолчания: после бетонной фазы их замеряют на этой машине и
фиксируют здесь (одним коммитом с выводом замера). Ужесточить порог можно, ослабить ради прохождения — никогда.

## Пол (всегда, без настройки)

- Нет новых подавлений проверок: `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `// oxlint-disable…`,
  `/* istanbul ignore */`, `v8 ignore`, `eslint-disable` — без строки рядом «почему + ID задачи» и без записи
  в «Исключениях». `@ts-expect-error` допустим только в тестах, проверяющих, что код **не** компилируется
  (например, «`Scope` нельзя собрать литералом»), с поясняющим комментарием.
- Нет отключённых и выборочных тестов: `.skip`, `.only`, `.todo`, `it.fails`, `describe.skip`, `test.fixme`; тесты
  не удаляются и не ослабляются (убранные проверки `expect`, «зелёный» snapshot вместо утверждения) без причины в
  итоге задачи и согласия ревьюера.
- Нет незавершённой работы: `throw new Error("Not implemented")`, пустой `catch {}`, `catch`, глотающий ошибку
  (в том числе `IsolationViolation`), `TODO`/`FIXME`/`XXX` без ID задачи (`// TODO(T-034): …`), заглушки
  «возвращаем фиксированное значение», закомментированный код.
- Нет секретов в коде и в git (только `.env.example`); `samples/`, `data/`, `models/`, `secrets/` — вне git.
- Этот файл, пороги в конфигурации (`vitest`, `.oxlintrc.json`, `.dependency-cruiser.mjs`, `tooling/checks/*`,
  `commitlint`, `lefthook.yml`) и `tooling/architecture/modules.ts` не ослабляются, чтобы изменение прошло.

## Архитектурные запреты (ревьюер проверяет строго; большинство ловит `make check`)

| Запрещено | Чем ловится |
|---|---|
| Импорт чужого модуля мимо `index.ts`; зависимость не из `dependsOn`; связь «вверх» | dependency-cruiser (`module-public-api-only`, `deps-of-*`) |
| Запрос к пользовательской таблице без `s.own(таблица)` на **каждую** таблицу; мимо `ScopedDb` (свой `drizzle()`, `pg`, `$client`, `unsafeRaw`); `crossTenant` вне `*.sweep.ts`; `SystemDb` у модуля без флага | аудитор SQL (`ISOLATION_VIOLATION`), dependency-cruiser, `tooling/checks/isolation.mjs` |
| `userId`/`householdId` во входной схеме процедуры, инструмента, нагрузке задачи; `makeScope`/`as Scope` вне входов | `isolation.mjs`, тест изоляции по реестру |
| `sql.raw` с данными; `sql`/`.execute` вне `infrastructure/db`; `db.query.*` (RQB) | `isolation.mjs`, ревью |
| `VIEW`, SQL-функции и триггеры над пользовательскими таблицами; таблица с `household_id` вне реестров; `household_id` nullable | проверка схемы (интеграционный тест) |
| Числа в `apps/web` (импорт `packages/calc`); `Date.now()`/`Math.random()` в `calc`; `float` для денег | dependency-cruiser, `calc-no-clock.mjs`, ревью |
| Вызов модели, HTTP или чтение файла внутри `s.transaction` | `LLM_IN_TRANSACTION` во время выполнения, ревью |
| Провайдеры `@ai-sdk/*` вне `llm`; `pg-boss` вне `platform/jobs`; `ai` и `@ai-sdk/react` на сайте вне `features/assistant`; `grammy` вне `telegram/infrastructure`; `better-auth` вне `identity/infrastructure`; `drizzle-orm` и `pg` вне `infrastructure/db` и `platform/db` (исключения: шаблонная БД `packages/testing/src/db`; `schema.ts` и `*.repo.ts` в `platform/{settings,secrets,rate-limit,jobs}`); `libpg-query` вне `platform/db`; внутренности `platform/db` (аудитор, `boss-db`) вне `platform/db`, `platform/jobs` и `main` | dependency-cruiser |

| Текст интерфейса литералом в JSX, бота, писем, уведомлений (только `t()`) | проверка литералов в `make check` |
| Текст переписки, содержимое документов, суммы с привязкой к пользователю, ПД — в логах и нагрузке задач; данные в строке сообщения лога | тест-канарейка логов, ревью |
| Тест, который ходит в интернет или тратит лимиты API (вне `make eval` и `make ai-record`) | кассеты в режиме `replay` по умолчанию: промах = ошибка |

## Как менять планку

1. Агент **не меняет** этот файл и пороги в конфигурации сам. Если порог мешает — `VERDICT: ESCALATE` (у критика и ревьюера — `ASK_USER`) с
   объяснением, замером и вариантами (оптимизировать, разделить задачу, временное исключение).
2. Ужесточение (выше покрытие, меньше бюджет) и калибровка чисел **[калибр.]** после бетонной фазы — главной сессией
   с согласия пользователя, отдельным коммитом `chore(tooling): …` с выводом замера; ослабление — только после явного «да» пользователя в чате,
   с записью даты и причины в «Последний пересмотр».
3. Ревьюер сравнивает этот файл и конфигурации проверок с состоянием на начало ветки: ослабление без записанного
   согласия — блокирующее замечание. Изменение `CONSTRAINTS.md` в одном коммите с кодом, который иначе не проходил,
   — тревожный признак.
