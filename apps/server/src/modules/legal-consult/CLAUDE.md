# Модуль `legal-consult`

Ярус 2 · таблицы: user (`checklist_progress`) · публикует: — (`docs/CAPABILITIES.md`; задачи — `tasks/plan.md`)

## Назначение
Правовой консультант (T-041): метки цитат `[[F…]]`, проверка дословности, «в моей базе нет», вопрос о прошлой дате, чек-листы документов и их
состояние. Ответ строит агент (T-042) по найденным фрагментам `legal-base`; модель **не пишет текст закона** — только метки, а `finalizeAnswer`
подставляет текст версии и проверяет всё остальное (P3). Данных пользователя в `finalizeAnswer` нет.

## Требования SPEC
LEGAL-01…12, CHAT-05/06/10, LAW-15, P3.

## Публичный API (`index.ts`)
- Фабрика: `createLegalConsultModule({ platform, facades })`; платформа — `Platform` (без `SystemDb`); фасады — `legalBase`, `normTables` (`rate`, LEGAL-08).
- Фасад `finalizeAnswer({ draft, topic, candidateActIds, asOf? })` → `LawAnswer`: `outcome` (`cited` | `no-base`), `parts` (текст и `cite n` — ссылка на блок), `citations`
  (`quote`: дословный текст версии, подпись «ст. 209, п. 1.1», «в редакции на 21.10.2026», ссылка pravo.by, `changedSince`, `notes` — предупреждения LAW-32;
  `link`: акт или статья без цитаты с пометкой — `no-text` | `quote-unverified` | `excluded` | `repealed` | `named`), `notices` (`past-date`, `rate`, `unresolved`, всегда
  последней `disclaimer` — LEGAL-07), `versionIds` (версии цитат: `chat` запоминает их для «статья изменилась после ответа», CHAT-10). Типы — `LawAnswer`, `LawCitation`,
  `LawNotice`, `LawPart`, `FinalizeInput`.
- Формат черновика (для подсказки агента, T-042): «цитата» `[[F<id версии из search_law>]]` — цитата прямо перед меткой; метка без цитаты подставляет текст версии целиком;
  `[[A<id акта>]]` — акт, названный ссылкой (акт без текста, LEGAL-06). Цитата в кавычках перед меткой проверяется `isVerbatim` (нормализация пробелов, кавычек, ё/е, дефисов, регистра;
  слово и число — только целиком; куски через «…» — по порядку, каждый не короче 3 слов, `MIN_PIECE_WORDS`), не прошла — снимается, вместо неё ссылка «цитата не прошла проверку». Цитата без метки не короче
  `legal-consult.free-quote-min-words` (6) слов проверяется по версиям этого ответа, не прошла — заменяется пометкой; название акта в кавычках — не цитата. Метка на версию, которой нет,
  или не того вида (`[[F12.2]]`) убирается и считается («N ссылок не удалось проверить»).
- «В моей базе нет» (LEGAL-04): ни одной подставленной нормы (в том числе при выдуманных метках) — текст черновика целиком заменяется ответом «в моей базе нет норм…», называются до трёх
  актов из `candidateActIds` (акт без текста — «текста нет, откройте по ссылке»), при `topic` — `legalBase.recordDemand({ topic, actIds })` (только тема и акты, без текста вопроса; сбой журнала — ключ
  `law.demand-failed`, ответ не падает, LAW-15).
- Вопрос о прошлой дате (LEGAL-08): `asOf: { day, param?, pravoId? }` — день раньше `legalBase.firstEditionOn(акт)` → оговорка «прежнюю редакцию процитировать не могу» и, если назван `param`,
  `normTables.rate(param, day)`: значение с источником и тем, кто подтвердил, либо «значения нет / ждёт подтверждения» (числа не называются). Сумму считает таблица, не модель (P1).
- Чек-листы (LEGAL-12): шаблоны `domain/checklists.ts` — вычет на обучение, на жильё, стандартные по ст. 209, возврат товара надлежащего качества, ненадлежащего (`claim-defective`), гарантия; пункт —
  шаг, документ или заметка, с инстанцией, сроком и нормой (`п. 3 ст. 210 НК`) и `evidence` — словами нормы, на которых он держится. Тексты — словарь `legal`, сумм и ставок в них нет (P1).
  Нормы вне сохранённых страниц (ст. 211, 222, 223 НК — `UNSAVED_REFS`) помечены `unsaved`, их пункты сверить по ссылке; тест `main/legal-consult.int.test.ts` находит каждую остальную норму точным
  обращением и сверяет `evidence` с текстом. Процедуры `legalConsult.checklists | checklist | setChecked` (`authed`) и инструмент `get_checklist` (набор `legal`, читает шаблон). Состояние —
  `checklist_progress` (строка на галочку; `general` | `message:<id>` | `deduction:<id>` без внешнего ключа: таблиц чата и вычетов ещё нет); галочка сама обратима, «Отменить» не регистрирует.
- Тексты — словарь `legal` (`createLegalT`, только сервер). Настройки: `legal-consult.free-quote-min-words`. События (`events.ts`): —; владелец данных — `user-data.ts`.

## Запреты

  — реестром корня композиции (ADR-0004).
- Данные домохозяйства — только через `s: ScopedDb` с `s.own(таблица)` на каждую таблицу запроса; новая таблица —
  `make new-table`, её строки — в `defineUserData` (`user-data.ts`).
- «Чьи данные» — только `s.scope`, никогда из входа процедуры, инструмента или нагрузки задачи.
