# Экран `setup` — Первый запуск системы

Маршрут: `/setup` (`routes/_local/setup.tsx`) · доступ: только localhost и только пока система не инициализирована
(иначе `beforeLoad` ведёт на `/login`; на сетевом входе сервер отвечает `NOT_FOUND`).

## Макет
- Исходник: `design/screens/Setup.dc.html`; описание — `design/SCREENS.md` § «Первый запуск системы».
- Скриншоты: `design/screenshots/desktop/Setup.png`, `design/screenshots/mobile-width/Setup.png`.

## Требования SPEC
AUTH-10, ROLE-02, ADM-01, SEC-01 (пароль ≥ 12), NFR-24; состояния — DES-16; доступность — NFR-20.

## Данные (контракт)
- Изменение: `orpc.identity.setup` (localOnly) — форма на схеме `SetupInput`; успех → шаг «Сохраните код
  восстановления» (код из ответа, один раз; `entities/recovery-code`; «Продолжить» — после «сохранил») →
  `/login?created=true`;
  `CONFLICT` (уже настроена) и `NOT_FOUND` (не локальный вход) → `/login`; прочее — текст `errors:<код>`.
- Охрана маршрута: `orpc.identity.status` → `setupAvailable`. Контекст ассистента: `staticData.page = "setup"`.

## Компоненты
Свои: `SetupPage`. Из `ui`: `Logo`. Mantine: `TextInput`, `PasswordInput`, `Button`.

## Переходы
После создания администратора — вход (`/login` с пометкой «Администратор создан»).

## Отличия от макета (с причиной)
- Шаги «Администратор» и «Код восстановления»; «Подготовка системы» (T-034, T-024) и поле «Контакт для загрузчика
  законов» (T-034) появятся со своими задачами — индикатор из трёх шагов пока не показан; «Скачать .txt» нет —
  «Скопировать» и запись вручную.
- Подсказка «Минимум 12 символов» вместо «10» макета: прав SPEC (SEC-01, ADR-0016).
