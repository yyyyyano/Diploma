# ADR-0003: Модульный монолит, карта модулей как код, три процесса

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** NFR-10, NFR-21, ROLE-01, PRIV-07, TG-10, LAW-35

## Контекст

SPEC описывает ~30 функциональных областей. Код пишут агенты, поэтому место каждого куска кода должно быть
предсказуемым, а границы — проверяться программой. Тяжёлые операции (HEIC, PDF, загрузчик законов) не должны
тормозить сайт; бот должен перезапускаться отдельно.

## Решение

- Раскладка: `apps/web`, `apps/server` (пакет `@kosht/server`), `packages/{kernel,calc,contract,i18n,testing}`,
  `e2e/`, `datasets/`, `tooling/`, `docs/`, `tasks/plan.md` (`docs/ARCHITECTURE.md` §2).
- Сервер — **модульный монолит**: 36 модулей в 4 ярусах (`docs/CAPABILITIES.md`) поверх `platform/` (ярус 0).
  Модуль = папка с фасадом `index.ts`; внутри `domain/` (чистое), `application/` (**сценарий = файл**, фабрика
  `make<Сценарий>(deps)`), `infrastructure/` (SQL и адаптеры), `api/`, `jobs/`, `subscriptions/`, `agent/`.
  **Порты — только на внешних границах.** Корень композиции `main/compose.ts` без DI-контейнера.
- **Карта модулей — код**: `tooling/architecture/modules.ts` (`id`, `tier`, `dependsOn`, `userData`, `systemTables`).
  Из неё генерируются правила dependency-cruiser («X может зависеть только от …»), таблица `docs/CAPABILITIES.md`
  и проверка порядка сборки. Зависеть можно от своего или нижнего яруса, без циклов.
- **Три процесса из одного кода**: `api`, `worker`, `bot` (`compose(config, role)`); общение — только через Postgres.
- Большой модуль делится на подпапки `application/` с одним фасадом; выделение подобласти в модуль — через ADR
  (сигнал: сценарий > 300 строк или > 25 файлов в `application/`). Мелкие модули можно слить без последствий для
  остальных — их id уже в карте.

## Альтернативы

- **Гексагональная архитектура на каждый модуль** — порт и адаптер на каждый репозиторий ×36: много шаблонного
  кода, тесты на фейках «зелёные» при сломанном SQL.
- **Вертикальные срезы без модулей** — быстро для фич, но «чьи это данные» и «админ не видит финансы» не
  проверить: срезы свободно лезут в общие таблицы.
- **Один процесс** — разбор PDF и HEIC тормозит чат; ошибка Telegram роняет сайт.
- **Пакет на модуль** — 36 `package.json` без выгоды: границы и так проверяются dependency-cruiser.

## Последствия

- Задача агента ≈ «новый файл сценария + тест» в предсказуемом месте; паспорт модуля говорит, что можно.
- Любая правка `modules.ts` — отдельный пункт итога задачи с обоснованием; связь «вверх» — только ADR.
- Тест порядка композиции и фикстуры нарушений на каждое правило границ обязательны (иначе правила могут молчать).
