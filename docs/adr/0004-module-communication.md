# ADR-0004: Связи модулей — фасад вниз, событие вверх, реестр для подстановки

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** NFR-21, NFR-22, OBS-01, BUD-03, TXN-10, P5

## Контекст

Модули должны вызывать друг друга без циклов и без «знаний наверх»: `transactions` не должен знать, что
`budgets` проверяет пороги, а `notifications` — что существует Telegram. Импорт 300 операций не должен порождать
сотни задач и дубли уведомлений.

## Решение

- **Фасад вниз**: нужен результат сейчас, в той же транзакции — вызов `facade` нижнего модуля с `tx`
  (`receipts` → `transactions.recordFromReceipt(tx, …)`).
- **Событие вверх**: `events.publish(tx, name, payload)` ставит задачу pg-boss в **той же транзакции** (outbox
  бесплатно); подписка — своя очередь `evt.<событие>.<слушатель>`; доставка «хотя бы раз» → обработчики
  идемпотентны; нагрузка — только id пачками (≤ 1000); пересчёты схлопываются `singletonKey` через `jobKey(scope, …)`
  с небольшой задержкой; порядок не гарантирован — обработчик перечитывает состояние.
- **Реестр** в корне композиции, когда верхний модуль подставляет реализацию вниз: каналы доставки уведомлений,
  словарь имён для маскирования, обработчики отмены и подтверждения (`actions`), владельцы данных (`privacy`),
  инструменты агента, настройки.
- Имена: события `<модуль>.<прошедшее время>` (`transactions.changed`), задачи `<модуль>.<глагол>`
  (`receipts.recognize`).

## Альтернативы

- **Прямые вызовы вверх** — циклы, «ком грязи».
- **Шина событий в памяти** — теряет события при падении процесса и не переживает перезапуск.
- **Брокер (Redis/BullMQ)** — лишний сервис, нет транзакционной постановки вместе с данными (ADR-0008).

## Последствия

- Реакция на событие приходит через доли секунды – секунды: тест «трата → уведомление 80 %» ≤ 3 с.
- Уведомления порогов идемпотентны по ключу «лимит + месяц + порог»; тест: импорт 300 операций → ≤ 5 задач
  пересчёта и ровно одно уведомление.
- Схемы событий — в `events.ts` публикующего модуля; подписаться может только модуль, у которого публикующий
  есть в `dependsOn`.
