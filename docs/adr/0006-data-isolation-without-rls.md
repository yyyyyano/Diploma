# ADR-0006: Изоляция данных пользователей без RLS — «пять замков»

- **Статус:** Принято (заменяет вариант «Scope + RLS» из отчёта 13 §2.7)
- **Дата:** 2026-10-24
- **Требования:** ROLE-01, SEC-04, PRIV-05, PRIV-06, PRIV-07, AGT-03, SEC-10, DIP-03

## Контекст

Чеки и операции всех домохозяйств лежат в общих таблицах. Одно забытое `WHERE household_id = …` — чужой чек на
экране; модель может подставить чужой id в аргумент инструмента (в том числе из-за текста на чеке). Пользователь
решил **не использовать RLS** Postgres. «Общий помощник + линтер + тест» держится на дисциплине: не ловит
затёртый `where`, JOIN к таблице без своего фильтра, сырой SQL и непокрытые ветки. Нужен замок, который смотрит на
**итоговый SQL**.

## Решение

Пять независимых замков — **типы** (`Scope` с брендом, `s: ScopedDb` первым аргументом), **схема** (PK и FK с
`household_id`, без «смешанных» таблиц), **аудитор SQL** в `Logger` Drizzle (каждое обращение к пользовательской
таблице ограничено `household_id` из scope, иначе `ISOLATION_VIOLATION` до отправки запроса; в продакшене — всегда
отказ), **статика** (dependency-cruiser, `isolation.mjs`, проверка схемы) и **тесты** по реестрам процедур и
инструментов с канарейками. Таблица замков, `ScopedDb`, места рождения `Scope`, `SystemDb`, `defineSweep` и
умолчания пользователя — `docs/ARCHITECTURE.md` §6; правила кода — `.claude/rules/database.md`.

## Альтернативы

- **RLS в Postgres** — решение пользователя «нет»; к тому же +70 мкс и 4 обращения к базе на запрос по схеме 13.
- **Только дисциплина (помощник + линтер + тест)** — пропускает 10 из 14 намеренных ошибок прототипа.
- **Свои урезанные билдеры поверх Drizzle** — сотни строк своего кода поверх быстро меняющихся типов RC.
- **Подзапросы-«представления»** — не покрывают UPDATE/DELETE/INSERT.
- **Схема или БД на пользователя** — ломает общий поиск по законам, миграции ×N.

## Последствия

- Забытый фильтр становится громкой ошибкой на первом запуске теста, а не тихой утечкой; в редкой непокрытой
  ветке в продакшене — 500 вместо утечки (осознанный компромисс; снижается покрытием репозиториев).
- Аудитор строже нужного: безвредный подзапрос без `own` тоже блокируется — правило «каждая таблица — свой `own`».
- Опора на порядок вызова `Logger.logQuery` в Drizzle 1.0 RC: версия закреплена точно, канарейки в `make test`;
  красные канарейки после обновления = стоп. Запасной путь — прокси над `pg.Pool`.
- Цена: 0,06–0,08 мкс на аудит запроса, 1,4 мкс на создание `ScopedDb`, индекс на каждую FK-пару.
- Семейный режим (DIP-03) — новая реализация `s.own()` с `visibility`, места вызова не меняются.
