# ADR-0007: PostgreSQL 18 + pgvector + pg_trgm, Drizzle 1.0 RC, русский полнотекстовый поиск + RRF

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** LAW-08, LAW-20…23, LAW-31, NFR-05, NFR-11, STMT-07, TXN-10

## Контекст

Нужны реляционные данные с транзакциями, векторный поиск по 20–30 тыс. фрагментов законов, полнотекстовый
поиск с русской морфологией, точные ссылки «ст. 210 НК», нечёткое сравнение названий магазинов — без внешнего
поисковика и платных расширений.

## Решение

- **PostgreSQL 18** (образ `pgvector/pgvector:<точный тег>-pg18-trixie`, том в `/var/lib/postgresql`, `uuidv7()`);
  расширения `vector` и `pg_trgm` — в первой ручной миграции.
- **Drizzle ORM 1.0 RC с точной версией** (`drizzle({ client, logger })`; запасной — 0.45.x) + `pg`. Запросы —
  построителем и `sql\`\``; **реляционный API `db.query.*` не используется**. Миграции — `drizzle-kit generate`,
  SQL читается глазами (HNSW, `CONCURRENTLY`, `ON DELETE SET NULL (колонка)` для составных FK — руками),
  применяются при старте под `pg_advisory_lock`; откатов нет (`make db-reset`). Таблицы pg-boss Drizzle не трогает
  (`schemaFilter: ["public"]`). Проверить в бетоне `casing: "snake_case"` — иначе писать имена колонок явно.
- **Векторы**: `halfvec`, HNSW (`m = 16`, `ef_construction = 64`), косинус; в запросе `hnsw.ef_search = 100` и
  `iterative_scan = relaxed_order`; таблицы `embedding_model` и `fragment_embedding`, частичный индекс на модель;
  векторы только у текущих версий фрагментов. HNSW — только для публичных данных; по пользовательским строкам —
  точный перебор после индекса `household_id`.
- **Полнотекстовый поиск**: встроенная конфигурация `russian`, `ё → е`, курируемый словарь «бытовое → юридическое»,
  двухэтапный запрос (сначала «И», при нехватке — «ИЛИ»).
- **Гибрид**: RRF (`k = 60`) двумя CTE + `FULL JOIN`, топ-10; веса и пороги — по набору QA-12.
- **Точные ссылки**: `act_alias` + btree `(act_id, article_no)`, ключ `216.1` для надстрочных номеров.
- **Версии**: `fragment` + `fragment_version` (`is_current`, `first/last_snapshot`, `text_hash`), частичный GIN по
  текущим; сырой HTML снимков — `act_snapshot` (gzip в `bytea`, только при изменении хэша).
- **Тестовая БД**: Postgres из Compose + шаблонная БД, своя база на каждый тестовый файл (`CREATE DATABASE … TEMPLATE`,
  ~20 мс), защита по префиксу `test_`.

## Альтернативы

- **Prisma** — `halfvec`/HNSW/`tsvector` только обходами; **Kysely** — нет описания схемы и миграций.
- **ParadeDB / внешний поисковик** — AGPL или вторая копия данных с синхронизацией версий.
- **Hunspell-словарь** — +6 п. п. полноты, но в 5 раз медленнее индексация и +250 мс на соединение.
- **PGlite для тестов** — неполный Postgres (расширения, pg-boss).

## Последствия

- Drizzle RC меняет API между версиями: обновление — отдельная задача с прогоном канареек аудитора (ADR-0006).
- Деньги — `bigint` копеек + `currency`; дни — `date`; моменты — `timestamptz`; `real/double` для денег запрещены.
- Замеры поиска и эмбеддингов на целевой машине — `make bench` (LAW-23).
