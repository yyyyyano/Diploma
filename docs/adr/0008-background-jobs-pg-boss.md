# ADR-0008: Фоновые задачи и события — pg-boss на том же Postgres

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** NFR-21, NFR-22, LAW-10, LAW-30, LAW-35, OBS-07, WEEK-01, CAL-07

## Контекст

Распознавание чеков, импорт выписок, загрузка законов (строго один поток к pravo.by), эмбеддинги, итоги недели,
напоминания идут в фоне; пропущенное из-за выключенного компьютера выполняется при запуске; событие модуля не
должно теряться и не должно появиться без записи данных.

## Решение

- **pg-boss 12** на основной БД; импортируется только в `platform/jobs` (правило границ). Задача — `defineJob({ name,
  payload: Zod, options: { priority, retryLimit, singletonKey }, handle })`; в нагрузке — только id (OBS-04);
  конверт несёт `scope` и `requestId`.
- **Транзакционная постановка**: `events.publish(tx, …)` и `jobs.enqueue(tx, …)` через `fromDrizzle(tx.db, sql)` —
  коммит даёт и запись, и задачу, откат — ни того ни другого (проверено через `ScopedDb`).
- **Расписания** с `missed: "once"` + «водяной знак» последнего обработанного периода в доменной таблице (once не
  говорит, сколько пропущено); ночное окно для массовых проходов законов (LAW-35).
- **Один поток к pravo.by**: мьютекс и пауза 3–5 с в загрузчике модуля `legal-base`; очереди `legal-base.*` обрабатывает
  только `worker` с одной копией обработчика.
- **«Для всех пользователей»** — `defineSweep` (ADR-0006): сквозной поиск id, затем задача на каждого под его scope.
- **Напоминания** — таблица `reminders` + тик раз в минуту (без отмены задач, догон бесплатный).
- **Прогресс и журнал** — таблица `background_job_run` (вид, статус, прогресс, ошибка) + API pg-boss → экран «Система».
- **Живые сигналы** — `LISTEN/NOTIFY kosht_realtime` (из `worker` в `api` → SSE), в сообщении только `householdId`,
  вид и id.

## Альтернативы

- **BullMQ + Redis** — лишний сервис, нет постановки в той же транзакции, что и данные.
- **Temporal** — тяжело для локального проекта.
- **pg_cron** — расписания без очереди и повторов.

## Последствия

- Всё фоновое — в `worker`; `api` только ставит задачи.
- `singletonKey` строится через `jobKey(scope, …)` — иначе дедупликация одного домохозяйства подавит задачу другого.
- Обработчики идемпотентны; повтор — только для `retryable` ошибок.
