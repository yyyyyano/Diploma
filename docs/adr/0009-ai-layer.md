# ADR-0009: ИИ-слой — Vercel AI SDK 7, шлюз `llm`, реестр моделей, инструменты `defineTool`, ожидающие действия

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** AGT-01…13, LLM-01…10, NFR-04, NFR-05, PRIV-02, PRIV-03, PRIV-09, SEC-10, SEC-11, LEGAL-03, P1, P5

## Контекст

Агент с инструментами — ядро системы уже в MVP. Провайдер меняется настройкой, при сбое запрос уходит
следующему; бесплатные лимиты узкие (Groq: 8 тыс. токенов/мин); без облачного согласия — только локальные модели;
личные данные маскируются; модель не может ни удалить данные сама, ни выбрать чужого пользователя, ни придумать
число или цитату.

## Решение

- **Vercel AI SDK 7** (`ai`, `@ai-sdk/react`) на сервере и сайте: цикл агента `ToolLoopAgent`, стриминг, структурные
  ответы, `useChat`. Провайдеры — `@ai-sdk/groq` и `@ai-sdk/openai-compatible` (Z.ai, llama-server). Свой тонкий
  слой сверху.
- **Шлюз `llm`** — единственный модуль, импортирующий `@ai-sdk/*` провайдеров (`ai` — только `llm`, `agent`, `chat`).
  Даёт `LlmGateway`: `model(scope, task)` («цепочка как одна модель» `LanguageModelV4`), `extract`, `classify`,
  `embed`, `transcribe`. Внутри: цепочки по задачам из **реестра моделей** (строки в БД с возможностями и ценами,
  R45), фильтр согласия `cloudAllowed`, лимитёр RPM/TPM/RPD по заголовкам и размыкатель, маскирование и
  демаскирование (текст, поток, аргументы инструментов), журнал расхода, трассы Langfuse (ADR-0010), запрет вызова
  внутри транзакции. Задачи без данных пользователя — через `systemCaller` (PRIV-09).
- **Маскирование**: правила + склонённый словарь имён (порт `KnownNames` ← `profile` через реестр) + локальная NER.
- **Агент** зависит только от `llm`, `actions`, `profile`, `legal-consult`: ≤ 8 шагов, последний — без инструментов.
  **Инструменты** лежат в модулях-владельцах (`agent/tools.ts`) и описываются своим `defineTool` из `platform/tools`
  (тип + Zod, без AI SDK); корень композиции собирает реестр; адаптер подставляет `ctx.s` из scope запуска.
  Виды: `read`, `write` (выполняется сразу, возвращает `undoToken`, AGT-05), `destructive` (только `propose` →
  ожидающее действие, AGT-07). Дозапрос — `ask_user` без `execute` (AGT-06).
- **Ожидающее действие** вместо `toolApproval`: строка в таблице модуля `actions`; «Да» на сайте и кнопка в Telegram
  вызывают одну функцию `actions.confirm`, действие исполняет код.
- **Токены**: 3–4 фиксированных набора инструментов (`core`, `legal`, `planning`, `reports`), постоянный префикс ради
  кэша провайдера, динамика — в конце; короткие английские описания; компактные результаты.
- **Стражи**: «вне темы» и защитный классификатор до цикла (правила → локальные эмбеддинги → малая модель);
  проверка чисел ответа (каждое число — из результатов инструментов); цитаты метками `[[F…]]` с программной
  подстановкой и проверкой дословности.
- **Тесты**: кассеты на границе шлюза (`ReplayModel`, режимы `replay | record | live`, ключ «сценарий + шаг»),
  моки `MockLanguageModelV4` для отказов и лимитов; eval (QA-10) — свой раннер на Vitest в модуле `quality` с бюджетом
  токенов и возобновлением.

## Альтернативы

- **LangChain / LangGraph / Deep Agents** — рассмотрены пользователем и отвергнуты: вес, второе хранилище
  состояния, лишние ~1 900 токенов инструментов на запрос (Deep Agents) — вернуться можно в дипломе (DIP-02).
- **Готовый `ai-fallback`** — общий для всех, не знает лимитов по моделям.
- **`toolApproval` / `interrupt`** — подтверждение из Telegram приходит отдельным событием, «возобновлять» нечего.
- **Модели, зашитые в код** — противоречит R45.
- **HTTP-кассеты (MSW/nock)** — ломаются при смене провайдера и подсказки.

## Последствия

- Мажоры AI SDK выходят раз в 5–6 месяцев с переименованиями — версия закрепляется, обновление отдельной задачей.
- Модель «вне транзакции» — правило ревью + проверка во время выполнения.
- Добавление инструмента дипломом (DIP-01/02/06) — новый `defineTool` в модуле, без правки агента.
- Пользователь без согласия — в трассах только локальный провайдер (КП PRIV-02, тест-инвариант).
