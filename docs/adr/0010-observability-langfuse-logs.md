# ADR-0010: Наблюдаемость — Langfuse self-hosted, журнал расхода в Postgres, pino-логи

- **Статус:** Принято (по R46 SPEC; заменяет «свои таблицы трасс» из отчётов 04 и 08)
- **Дата:** 2026-10-24
- **Требования:** NFR-15, OBS-01…07, LLM-05, LLM-06, ADM-20…22, PRIV-06, PRIV-07

## Контекст

Нужно видеть каждое обращение к ИИ (шаги агента, инструменты, токены, ошибки, тексты), считать лимиты бесплатных
тарифов в реальном времени, показывать админу основные цифры без текстов, а в логах приложения не держать
личных данных. Пользователь выбрал Langfuse: «профессиональнее, учебный проект без жёстких требований к секретности».

## Решение

- **Langfuse v4 self-hosted** в профиле Compose `observability`: web + worker, свой Postgres, ClickHouse (лимит памяти
  ~3 ГБ), Valkey (`noeviction`), SeaweedFS вместо MinIO (MinIO заархивирован). **Включён по умолчанию** (OBS-05),
  выключается настройкой окружения; доступен только на `127.0.0.1:3001`; регистрация закрыта
  (`AUTH_DISABLE_SIGNUP`), первый пользователь — через `LANGFUSE_INIT_*`, телеметрия Langfuse выключена.
- **Тексты пишутся** (R46): запросы, ответы, шаги, инструменты; `userId` — внутренний id пользователя (не email),
  `sessionId` — id диалога. Хранение 30 дней — своя ночная задача через API удаления (Data Retention у Langfuse
  только в EE); при удалении аккаунта (PRIV-06) удаляются трассы пользователя. Глубокой криптографии нет.
- Подключение: интеграция OpenTelemetry AI SDK 7 (`@ai-sdk/otel`, `registerTelemetry`) + `@langfuse/otel` — T-011;
  пакета `@langfuse/vercel-ai-sdk` для AI SDK 7 нет (уточнено в T-010). Порт `platform/telemetry` (T-010) уже отдаёт
  каждому вызову опции `telemetry` (`functionId`, `includeRuntimeContext`) и `runtimeContext` с `userId` и
  `sessionId`; до подключения трассы выключены. Версии пакетов OpenTelemetry **закреплены** (иначе импорт
  `@langfuse/otel` падает).
- **Журнал расхода** в Postgres (модуль `llm`, LLM-06): строка на вызов — задача, провайдер, модель, токены,
  длительность, условная стоимость, ошибка, без текстов; 90 дней. Из него — лимиты (скользящие окна в памяти +
  восстановление из журнала + заголовки провайдера) и экран «Запросы к ИИ» (ADM-20) со ссылкой «Подробные трассы —
  в Langfuse». Работает при выключенном Langfuse.
- **Логи приложения** — pino: JSON, `AsyncLocalStorage` (`requestId`, `uid`, `source`), сообщение — стабильный
  английский ключ события, данные — полями из белого списка; поля вне белого списка отбрасываются до pino (поэтому `redact` не нужен), `scrub()` для ошибок, тест-
  канарейка «ПД не попали в лог»; ротация ежедневно, 14 файлов (`pino-roll`); `pino-pretty` в разработке.
  Сквозной `requestId` идёт от HTTP/Telegram через задачи до вызова модели (OBS-01).

## Альтернативы

- **Свои таблицы трасс `ai_call`/`ai_step`** (отчёты 04, 08) — нельзя случайно сохранить текст, но нет удобного
  разбора поведения агента; отвергнуто R46.
- **Режим разработки с текстами только по переменной** (R23, R39) — заменён R46.
- **LangSmith** — облако, противоречит P7.
- **Langfuse выключен по умолчанию** (рекомендация отчёта 12) — противоречит OBS-05 и решению пользователя.

## Последствия

- Профиль `observability` стоит ~2 ГБ памяти в простое (до ~5,8 ГБ под нагрузкой) — приемлемо из 36 ГБ.
- Админка не зависит от Langfuse; в ней нет текстов (ADM-22, PRIV-07).
- В логах — только id и ключи событий; суммы с привязкой к пользователю, тексты переписки и документов — никогда
  (OBS-04). Нарушение — блокирующее замечание ревью.
