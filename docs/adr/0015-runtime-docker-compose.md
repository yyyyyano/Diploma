# ADR-0015: Запуск — один Docker Compose с профилями, два режима, Docker Engine

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** NFR-01, NFR-14, NFR-24, NFR-25, OBS-05, OBS-06, AUTH-06, AUTH-10, R40

## Контекст

Система запускается одной командой (NFR-01). Разработчику удобно «инфраструктура в контейнерах, код на хосте»
(мгновенная перезагрузка), на защите — «всё в контейнерах». Локальным моделям нужен доступ к iGPU. Экран первого
запуска и почтовый ящик должны быть недоступны из сети.

## Решение

- **Один `compose.yaml`** с профилями: без профиля — `db` (PostgreSQL 18 + pgvector, `127.0.0.1:5440`, том в
  `/var/lib/postgresql`, healthcheck); `app` — `api`, `worker`, `bot` из одного образа; `models` — llama-server и
  whisper.cpp; `observability` — Langfuse (ADR-0010, включён по умолчанию); при необходимости `tools`.
- **Режим А `make dev`**: `db`, `models`, `observability` в контейнерах, приложение на хосте (`node --watch`, Vite).
  **Режим Б `make up`**: всё в контейнерах (`make init && make up` на чистой машине). Один и тот же `./data/…` в обоих.
- **Образ**: `pnpm fetch` + сборка точек входа tsdown, базовый `node:26-trixie-slim` (glibc для нативных модулей),
  `USER node`, `read_only`, `cap_drop: ALL`, `init: true`; миграции — самим приложением при старте под
  `pg_advisory_lock`; корректное завершение по `SIGTERM`.
- **Docker Engine**, не Desktop (Desktop в виртуальной машине, iGPU не пробрасывается); GPU — `devices: /dev/dri` +
  `group_add: ${RENDER_GID}` (число, записывает `make init`); пользователь сам добавляет себя в группы `docker` и
  `render`; `make doctor` проверяет контекст, группы, порты.
- **Порты публикуются всегда с адресом**: `127.0.0.1:8140` (локальный вход), `8141` (сетевой, слушатель открывается
  из админки), `127.0.0.1:8142/8143` (модели), `127.0.0.1:3001` (Langfuse). У переменных профильных сервисов —
  значения по умолчанию (`${RENDER_GID:-992}`), `down` — с `--profile '*'`.
- **Тома**: именованный `pgdata`; bind mount `./data/{files,logs,backups,exports,models}` (модели — тоже bind, как
  файлы: одни пути в обоих режимах, видны на хосте, загрузчик пишет, llama и whisper читают `./data/models:/models:ro`;
  изменено в T-024, прежде был именованный том `models`); `secrets/` (мастер-ключ,
  пароль БД) через Compose `secrets:`; лог-драйвер `local` с лимитом размера.
- Горячая перезагрузка — только в режиме А (`compose watch` и bind mount репозитория — нет: симлинки pnpm и нативные
  модули).

## Уточнения при внедрении (T-011)

- **Модели** (`models`) стартуют только с `WITH_MODELS=1` (T-024: загрузчик приложения скачивает их сам, но сервисы по-прежнему
  не обязательны — без них пользователи без облачного согласия остаются без модели). Образы —
  тег сборки и digest: `llama.cpp:server-vulkan-b11854`, `whisper.cpp:main-vulkan-<коммит v1.9.5>` (образ whisper.cpp
  с Vulkan есть, тег — по коммиту).
- **Пользователь контейнеров приложения** — пользователь хоста (`user: ${APP_UID}:${APP_GID}`, пишет `make init`;
  в образе — `USER node`, uid 1000): секреты Compose — bind mount с правами хоста (0600), а `./data` — общая с
  `make dev`; иной uid хоста иначе не прочитал бы секреты и не записал бы логи.
- **Секреты Langfuse** — не Compose `secrets:`, а `env_file` из `secrets/` (`make init`, `tooling/langfuse-secrets.ts`):
  образы Langfuse, ClickHouse, Valkey читают их только из окружения, а Langfuse работает не от root и смонтированный
  файл 0600 не прочитает. Ключи проекта для приложения — Compose `secrets:` (`LANGFUSE_*_KEY_FILE`).
- **S3 Langfuse** — SeaweedFS `weed mini -bucket=langfuse` (всё в одном, ведро создаётся при старте; учётная запись —
  `AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY`): отдельный одноразовый контейнер для ведра не нужен.
- **Сетевой порт** публикуется как `0.0.0.0:8141` — адрес указан явно, слушатель закрыт настройкой админки.
- `make doctor` проверяет и порт Vite `5173` (`make dev` с `strictPort`); группы — и по базе групп, и в текущем сеансе.
- Папка миграций — переменная `MIGRATIONS_DIR` (в образе `/app/drizzle`), а не путь от `import.meta.url`.

## Альтернативы

- **Два Compose-файла** или `compose.override.yaml` — легко получить «пол-системы» или неявное поведение.
- **Отдельный контейнер-мигратор** — неоднозначность `--wait` с одноразовыми сервисами.
- **Mailpit** вместо своего локального ящика — английский интерфейс, отдельный порт, мимо «охранника» localhost.

## Последствия

- `make up` тяжелее из-за Langfuse (~2 ГБ в простое) — принято.
- Docker до 28.3.3 имел уязвимость с портами `127.0.0.1` после перезагрузки firewalld — `make doctor` проверяет версию.
- Резервная копия — `make backup` (`pg_dump -Fc` + файлы) и кнопка в админке; мастер-ключ в копию не входит.
