# ADR-0017: Расчёты в `packages/calc` с трассой и «Откуда эта цифра?»

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** P1, P2, EXPL-01, EXPL-02, FIN-01, AGT-04, TAX-01…07, AFF-03, BUD-05, RCPT-05, XLS-02, NFR-11

## Контекст

Любое число в интерфейсе и в ответе ассистента считает детерминированный код (P1) и объяснимо до операций и норм
закона (P2). Объяснение показывает именно тот расчёт, которым получено число (EXPL-02), а не пересчитанный заново.
Калькулятор вычетов, ПДН, сценарии покупки, валидатор чека — самые ответственные места и требуют быстрых тестов.

## Решение

- **`packages/calc`** — все финансовые, налоговые и проверочные расчёты; зависит только от `@kosht/kernel`; ни БД,
  ни сети, ни `Date.now()`, ни `Math.random()` (правило `calc-only-kernel` + `tooling/checks/calc-no-clock.mjs`).
- Каждая функция возвращает **`Calc<T> = { value: T; trace: TraceNode }`**; `TraceNode` — `{ key, op, value, inputs[],
  refs[], note? }`, `key` — ключ подписи в словаре `formulas` (i18n), `refs` — операции, версии фрагментов норм, курсы.
- «Сегодня», ставки (`norm-tables`), пороги (настройки) — **входы** функции.
- **Деньги** — `Money { minor, currency }` в целых копейках; проценты и ставки — базисные пункты или десятичные
  строки; округление — явное и только в `calc`. `float` для денег запрещён.
- **`explain`** (модуль яруса 1) хранит трассу рядом с результатом: модуль, показывающий число, вызывает
  `explain.save(s, calc)` и отдаёт `traceId`; сайт показывает `WhyButton` → панель по `traceId`; агент — инструмент
  `explain_number`.
- Агенту арифметика недоступна: инструмент `calculator` считает выражения над числами из результатов других
  инструментов через `calc` и пишет трассу; страж проверяет, что каждое число ответа есть в результатах.
- Сайт денег не считает (правило `web-only-shared-packages`).

## Альтернативы

- **Расчёты внутри модулей** — нет единой трассы, тесты требуют БД, легко посчитать дважды по-разному.
- **Пересчитывать объяснение по запросу** — нарушает EXPL-02 (данные могли измениться).
- **Числа на клиенте ради отзывчивости** — расхождение с ответом ассистента, нет объяснения; исключение — только ADR.

## Последствия

- Самая высокая планка покрытия в проекте — у `calc` (`CONSTRAINTS.md`); все примеры TAX-07 и КП AFF/BUD/REC — тесты.
- Трассы занимают место в БД (`explain`) — принимается; удаляются вместе с данными пользователя.
- Новый показатель = функция в `calc` + ключ подписи в `formulas` + тест-пример из SPEC.
