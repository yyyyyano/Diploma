# ADR-0018: Конвейер агентов разработки, паспорта модулей и правила

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Требования:** NFR-10, NFR-11, NFR-17; SPEC §0 «Документы живые»

## Контекст

Код пишут ИИ-агенты, человек читает выборочно. Нужны: проверка задачи до кода, независимое ревью, ограничение
циклов «правка–ревью», строгое соблюдение архитектуры и конвенций, правила, которые грузятся только там, где нужны,
и защита от ослабления проверок ради «зелёного».

## Решение

- **Роли** в `.claude/agents/`: `critic` (Sonnet) → `implementer` (Opus) → `reviewer` (Sonnet) → `fixer` (Sonnet,
  эскалация на Opus: второй заход, `risk: high`, правка вне одного модуля, `ESCALATE`). Не больше 3 ревью и 2 правок,
  затем остановка и вопрос пользователю. Вложенные сабагенты в конвейере запрещены.
- **Нарезка работы**: строго последовательно, по одной задаче; задача плана — крупный цельный кусок тесно связанной
  работы (модуль или экран целиком), а не мелкий шаг; ветка на задачу, после приёмки — перемотка в `main`
  (в `auto` сразу, в обычном режиме — после «да»); `auto` останавливается после N задач (по умолчанию 5) ради
  контекста; задача — модуль вместе со своей частью экранов (`docs/ARCHITECTURE.md` §10.5).
- **Оркестрация** — команда `/task-cycle <ID>`; `/task-cycle auto` — задачи подряд до точки остановки (список —
  `.claude/commands/task-cycle.md`).
- **Передача результатов** — без файлов-отчётов: каждая роль возвращает итог ответом в главную сессию (первая
  строка `VERDICT: …`); итоговый отчёт пользователю — в чате; в `tasks/` один файл `tasks/plan.md` — фазы и крупные
  задачи со статусами.
- **Ревьюер** проверяет не только качество кода (5 осей), но и **строгое соблюдение архитектуры, конвенций,
  паспортов и правил**; отступление допустимо только с веской причиной, записанной в итоге задачи (и ADR, если меняет
  правило); шестая проверка — «планка не занижена» (`CONSTRAINTS.md`).
- **Правила для агентов** — гибрид: корневой `CLAUDE.md` (≈ 130 строк, то, что нужно в каждой задаче); паспорт
  `CLAUDE.md` в каждом модуле, фиче и пакете (≤ 60 строк, шаблоны `docs/templates/`, создаются в бетонной фазе
  сразу для всех 36 модулей — коротко); сквозные темы — `.claude/rules/*.md` с `paths:` (≤ 60 строк). Источник
  правды по границам — `modules.ts` и `.dependency-cruiser.mjs`; правила объясняют «почему» и ссылаются, а не копируют.
  Роли обязаны прочитать паспорта затронутых модулей и правила по путям задачи (ленивая загрузка не срабатывает на
  Grep/Glob).
- **Хуки** Claude Code (`.claude/hooks/`, `settings.json`): запреты git (`push`, `--no-verify`, переписывание истории),
  права ролей на запись, формат после правки, гейты `SubagentStop` (гейт сам запускает `make check`, а не верит отчёту).
  Git-хуки — lefthook (ADR-0001).
- **Планка** — `CONSTRAINTS.md` по скиллу constraint-driven-development; меняет только главная сессия и только с
  согласия пользователя (роли — нет, это запрещает хук).
- `~/University/CLAUDE.md` для проекта исключён (`claudeMdExcludes`), нужное перенесено в корневой `CLAUDE.md`.
- Язык правил и паспортов — русский; машинные имена — английские.

## Альтернативы

- **Только ручной шаг** вместо `auto` — пользователь выбрал оба режима.
- **Workflow-скрипт** вместо команды — не умеет спросить пользователя посреди прогона; запасной путь.
- **Только вложенные `CLAUDE.md`** или **только `rules/`** — сквозные темы размазаны или правила далеко от кода.
- **Плагинные агенты** — хуки и `permissionMode` в них игнорируются.

## Последствия

- След задачи — коммиты ветки, статус в `tasks/plan.md` и итог в чате; лишних документов нет.
- Изменение паспорта, публичного API, зависимостей или запретов модуля — в том же коммите, что и код.
- Ослабление планки, правка `modules.ts`, новый ADR — всегда видимые пункты итога задачи.
