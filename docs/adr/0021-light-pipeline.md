# ADR-0021: Лёгкий конвейер — критик на фазу, одно ревью, решения посреди фазы без вопросов

- **Статус:** Принято
- **Дата:** 2026-10-25
- **Требования:** NFR-10, NFR-17; SPEC §0 «Документы живые»

## Контекст

Конвейер ADR-0018 (критик на каждую задачу, до 3 ревью и 2 правок, вопрос пользователю на каждой развилке) в фазе 1
оказался долгим: критик почти на каждой задаче предлагал разрез и плодил новые задачи (T-056…T-061), ревью шло по
4–6 кругов, а пользователя останавливали посреди фазы. Пользователь решил (2026-10-25): вопросы — только в начале
фазы, всё остальное агенты делают сами.

## Решение

- **Критик — один раз перед фазой** (`/task-cycle`, шаг A): проверяет все оставшиеся задачи фазы, правит тексты
  существующих задач (критерии, объём, перенос критерия в более позднюю задачу фазы), пишет «Уточнения критика»
  в каждую задачу и задаёт вопросы пользователю — единственные за фазу. **Новых задач и ID не создаёт.**
- **План не растёт** (уточнение пользователя 2026-10-25): после планирования новые задачи и ID не появляются ни от
  критика, ни от дирижёра, ни от ролей. Изменение — правка существующей задачи (скорректировать, дополнить,
  перенести критерий, убрать как `dropped`); находка «на потом» — критерием в подходящую существующую задачу.
- **По задаче:** `implementer` (Opus) → дирижёр сам гоняет `make check`/`make test-int` → **одно лёгкое ревью**
  `reviewer` (Sonnet, блокируют только невыполненный критерий, деньги/права/изоляция/секреты, заниженная планка,
  явная поломка архитектуры) → при находках **одна правка** `fixer` (Opus на `Риск: high`) → дирижёр перезапускает
  проверки и принимает задачу. Второго ревью нет.
- **Посреди фазы решает дирижёр:** развилки, `ESCALATE`, `disputed` — рекомендованный обратимый вариант, запись в
  блок «Решено без пользователя» в `tasks/plan.md`, перечень в отчёте конца фазы. Задача останавливается только
  если её нельзя довести без нарушения планки (`blocked`).
- **Документы правит дирижёр** без отдельного согласия: `CONSTRAINTS.md`, `.claude/**`, `docs/**`, тексты задач.
  Роли `implementer`/`fixer` сами правят `.claude/rules/*.md` (устаревшее из-за правки правило — в том же
  коммите); прочее предлагают ответом. ADR, написанный ролью, дирижёр может принять сам, если решение обратимо.
- Остальное из ADR-0018 (роли, ветка на задачу, перемотка в `main`, ответы без файлов-отчётов, паспорта, правила по
  маскам, «планка не занижена») — в силе. Если `main` ушёл вперёд ветки задачи — `git merge main` в ветку, без rebase.

## Альтернативы

- Оставить ADR-0018 как есть — отвергнуто: долго, много вопросов и новых задач.
- Без критика вовсе — отвергнуто: фаза 1 показала, что проверка критериев до кода экономит круги ревью.
- Без ревью — отвергнуто: ревью в фазе 1 находило реальные дыры изоляции и утечки ПД в логи.

## Последствия

- Фаза идёт без остановок от вопросов; цена — решения «без пользователя», которые он пересматривает по отчёту фазы.
- Одно ревью ловит меньше, чем пять: тяжесть переносится на имплементатора (критерии доказываются тестами) и на
  автоматические проверки (`make check`, `deps-check`, `static-checks`, аудитор SQL).
- Хук `guard-writes.sh` пускает `implementer`/`fixer` в `.claude/rules/*.md`, остальное в `.claude/` — по-прежнему нет.
