# ADR-0022: Разбор недоверенных файлов — песочница `worker_threads`, свои библиотеки чтения, приём в `files`

- **Статус:** Предложено
- **Дата:** 2026-10-29
- **Требования:** SEC-03, STMT-03, STMT-04, STMT-05, NFR-11, NFR-18; ARCHITECTURE §11.2

## Контекст

Выписки приходят от пользователя в PDF, XLSX, XLS, CSV и сканах. Это недоверенный ввод: «бомба» в ZIP внутри XLSX,
PDF, который читается минутами, файл, съедающий память. Падение разбора не должно ронять `api` и `worker`.

## Решение

- **Песочница** (`platform/sandbox`): `runIsolated(worker, input, { timeoutMs, memoryMb })` запускает рабочий файл в
  `worker_thread` с `resourceLimits` и `terminate()` по таймауту; сбой — `SandboxError` без текста исключения. Общий
  помощник выписок и чеков (T-027). Рабочий файл — `*.worker.ts` (в `make dev`) или отдельная точка входа tsdown
  `<имя>.worker.mjs` рядом с бандлом (образ); выбор по расширению файла помощника (`workerUrl`). Проверка — тест,
  который собирает бандл tsdown и запускает его node.
- **Чтение:** PDF — `unpdf` (слова с координатами → строки и ячейки; колонки по шапке); XLSX/XLS — SheetJS CE 0.20.3
  из тарболла `vendor/xlsx-0.20.3.tgz` (в npm — заброшенная 0.18.5 с уязвимостями); CSV — `papaparse`, кодировка по BOM,
  строгому UTF-8 и запасному windows-1251; скан — картинки (`unpdf.extractImages` + `sharp`, без `@napi-rs/canvas`)
  модели с изображениями. Перед SheetJS — защита от ZIP-бомб по центральному каталогу архива (число записей, суммарный
  размер, коэффициент сжатия). Библиотеки разбора — только в `statements/infrastructure` (правило
  `document-parsers-only-in-statements-infrastructure`), `sharp` — ещё и там.
- **Приём** (`files`): тип по содержимому (`file-type`) + белый список вида; расширение, не подходящее найденному
  типу, — отказ; лимиты — настройки (фото 15 МБ, выписка 25 МБ, 10 файлов); `POST /api/files` (multipart) с отдельным
  пределом тела `http.upload-body-limit-bytes`: Hono обрывает тело до чтения.
- **Колонки:** запомненный формат → словарь заголовков → модель по замаскированному фрагменту (только смысл колонок);
  строки разбирает код, цепочку остатков сверяет `calc`.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Отдельный дочерний процесс | Тяжелее по запуску и обмену данными; `worker_threads` с `resourceLimits` и `terminate()` достаточно для одного пользователя |
| `xlsx@0.18.5` из npm | CVE на разбор и ReDoS, не обновляется |
| `pdf-parse`, `pdfjs-dist` напрямую | `unpdf` — тот же pdf.js без canvas, с `extractImages` |
| Отдельный разборщик под каждый банк | Против STMT-05 и R44 |

## Последствия

- Каждый новый разбор недоверенного файла (чеки, T-027) идёт через `runIsolated`; рабочий файл — своя точка входа tsdown.
- Многострочные заголовки PDF (шапка таблицы в две строки) не поддерживаются: колонки такой выписки определит модель.
- Откат: библиотеки заменяются в `statements/infrastructure/parsing`, порт `DocumentReader` не меняется.
