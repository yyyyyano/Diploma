# Пакет `@kosht/e2e` — сквозные сценарии сайта и доступность (Playwright + axe)

## Назначение
5–8 ключевых сценариев и axe на каждом маршруте при 1440 и 390 px (ARCHITECTURE §12, CONSTRAINTS «Доступность»).
Отдельный пакет: настоящий браузер и сборка сайта, а не jsdom.

## Кто использует
`make e2e` (и `check-full`); браузер — `make e2e-install` (Chromium версии `@playwright/test` из `catalog:`).

## Публичный API
- `playwright.config.ts`: сборка `vite build --mode e2e --outDir dist-e2e` и стенд
  `apps/server/src/entrypoints/__fixtures__/e2e-stack.ts` на `127.0.0.1:8150` (`E2E_PORT`): api и worker на своей
  свежей базе (клон шаблона тестов), сайт отдаёт api, модели — кассета `chat/accounts` (replay с паузами записи);
  остановка — SIGTERM (`gracefulShutdown`), стенд удаляет базу. Правовая база — без сети: `LEGAL_SOURCE=fixtures` и
  `LEGAL_FIXTURES_DIR` (сохранённые страницы `legal-base/__fixtures__/pravo-by`): после первого запуска стартовый каталог
  грузится сам — три акта с текстом, остальные «только карточка» (NFR-11).
  Локаль ru-RU, пояс Europe/Minsk, Chromium.
- `specs/*.spec.ts`: `gallery.spec.ts` — витрина `/dev/gallery`: axe (`wcag2a`, `wcag2aa`, `wcag21aa`,
  `wcag22aa`) с закрытыми и открытыми панелью, подтверждением, уведомлением, шторкой «Ещё»; нет горизонтальной
  прокрутки; шрифты — со своего адреса, чужих запросов 0 (DES-09). `first-run.spec.ts` — чистая база: «/» → первый
  запуск → администратор → код восстановления (один раз, «Продолжить» после «сохранил») → вход → анкета на 1 минуту
  (первый вопрос, остальные пропущены, «Вот что я запомнил») → «Наличные · 0,00 BYN» → «Ассистент» (первое событие потока ≤ 1 с, ответ по кускам
  ≥ 1,5 с, карточка счёта; закрытая вкладка — ответ дописан) → «Администрирование» (`/admin/users`, `/admin/system`) → выход; axe и прокрутка на `/setup`,
  `/login`, `/onboarding` (вопрос и итог), `/accounts`, `/assistant`, `/admin/users`, `/admin/ai-providers`, `/admin/ai-requests` (и `?period=week`), `/admin/system` при 1440 и 390 (перед axe — конец переходов). `registration.spec.ts` — свой пользователь (email с меткой времени):
  `/policy` → регистрация (без согласия на ПД кнопка неактивна) → «Аккаунт создан» → «Не подтверждён» в настройках →
  письмо в `/mailbox` → `/verify-email` → повтор ссылки — отказ → выход и вход; axe на `/policy`, `/register`,
  `/settings`, `/mailbox`, `/verify-email`. `recovery.spec.ts` — свой пользователь → выход → «Забыли пароль?» →
  письмо сброса в `/mailbox` → новый пароль по ссылке → повтор ссылки — отказ → вход с новым паролем (старый — нет);
  axe на `/login`, `/recovery` (запрос, вход с кодом, новый пароль), `/settings`. `my-data.spec.ts` — свой
  пользователь → облачное согласие (окно) дать и отозвать → архив собирает worker, ссылка скачивает ZIP, уведомление
  «архив готов» → удаление аккаунта с паролем → вход тем же паролем — отказ; axe на `/settings?tab=privacy` (с окном
  согласия) и `?tab=my-data` (до и после архива, с окном удаления). `profile.spec.ts` — свой пользователь → анкета
  пропущена и больше не показывается → `/memory`: «Указать» факт в окне, удалить сразу, «Отменить» — факт вернулся; axe
  на пустой странице, с окном формы и со списком. `accounts.spec.ts` — свой пользователь → «Наличные» и итог в BYN → ⓘ итога (панель) → новый вклад с начальным
  остатком → переименование и «Отменить» → удаление после «Да»; axe на списке, панели, окне нового счёта и
  подтверждении (только BYN: курсы НБРБ стенд не запрашивает). `recurring.spec.ts` — свой пользователь → «Регулярные платежи»: пусто, «Добавить вручную» (окно), платёж в «Обязательных» и «Отменить», исправить сумму, «Это не регулярный» и «Отменить»; axe на пустой странице, окнах и списке (найденные поиском платежи — int-тесты на истории из `@kosht/synth`). `operations.spec.ts` — свой пользователь → загрузка
  (ответ списка придержан), пусто, ошибка (503) → ввод операции (окно, категория из списка) → строка и «Записал…» →
  карточка → правка суммы → удаление после «Да» и «Отменить» → вторая операция, выбор обеих, «Сменить категорию» с
  вопросом и «Отменить» → фильтр без результата; axe на каждом состоянии (в том числе с выбором и открытым вопросом). Сценарии со своим пользователем после первого входа
  пропускают анкету.
- `specs/support/undo-toast.ts` — `holdUndoToast(page, текст)`: ждёт уведомление «… [Отменить]» без предела в 5 с и
  держит его фокусом на «Отменить» (пауза WCAG 2.2.1); уведомление живёт 5 с, и под нагрузкой тест не гонится за ним.
  Перед axe на появившемся окне или списке — `shownSettled(locator)` (`specs/support/settled.ts`): элемент с предками
  непрозрачен и конечные анимации не идут (переход Mantine начинается кадром позже монтирования); бесконечные мерцания не ждём.

## Можно зависеть от
`@playwright/test`, `@axe-core/playwright`. Нельзя: импорт кода `apps/*` (сценарии видят сайт как пользователь).

## Запреты
- Походы в интернет (`e2e/` — правило ARCHITECTURE §2): чужой запрос — падение теста.
- Ослабить axe (теги, исключения правил), чтобы прошло (CONSTRAINTS «Пол»).

## Как тестировать
- `make e2e`; отчёты и трассы падений — `e2e/test-results/` (вне git).

## Подводные камни
- База стенда — одна на прогон: первый запуск проходит один раз, поэтому сценарий со входом — один и
  последовательный; новые сценарии со своими данными заводят своих пользователей регистрацией (ящик общий — письмо
  ищется по своему email).
- Пароль — `getByLabel("Пароль", { exact: true })`: у кнопки «Показать пароль» в имени тоже есть «пароль».
- Новая версия `@playwright/test` требует свою сборку Chromium — после обновления `make e2e-install`.
