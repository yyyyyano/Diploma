## Коротко: что рекомендую

Vite 8 + React 19 + **TanStack Router** (одностраничное приложение без сервера на стороне фронта) →
**Mantine 9** как единственный UI-кит (в нём уже есть таблицы-обёртки, даты, графики, календарь событий,
загрузка файлов, уведомления, командная палитра, формы) → чат на **`useChat` из AI SDK** поверх открытого
потокового протокола (SSE), а карточки и шаги агента — свои компоненты на Mantine → формы на
**Mantine Form + те же Zod-схемы, что на бэкенде** → тексты через **i18next** → тесты на **Vitest 5 + Playwright
+ axe**, без Storybook. Шрифты — `@fontsource-variable/*`.

## 1. Каркас: чем собирать и как делать маршруты

**Что решаем.** Чем собрать приложение и какой роутер взять. Приложение живёт только на localhost, поисковики
не нужны, бэкенд — отдельный Node-сервер. Пример: когда на дашборде вы выбираете «сентябрь» и кликаете
по категории «Такси» (`DASH-03`), в адресе должно появиться `…/operations?period=2026-09&category=taxi`,
и страница, которую агент видит как «контекст» (`CHAT-08`), берётся прямо из адреса.

| Вариант | Суть | Плюсы | Минусы | Версия, дата [В] | Лицензия |
|---|---|---|---|---|---|
| **Vite 8 + React 19 + TanStack Router** | Статический SPA; маршруты и параметры адреса проверяются типами | Параметры адреса (`period`, фильтры) описываются Zod-схемой и типизированы, `Link` не даст ошибиться в параметрах; автоматическое разбиение кода по маршрутам; нет серверной части | Сообщество меньше, чем у React Router; файловая генерация маршрутов — ещё один плагин | Vite 8.3.5 (стабильный Vite 8 — 2026-03-12), `@tanstack/react-router` 1.170.46 (2026-10-22), `@vitejs/plugin-react` 6.1.2 | MIT |
| Vite + React Router 8 (режим данных) | Классический роутер, v8 вышла 2026-06-17 | Самый распространённый; ничего лишнего | Параметры адреса — обычные строки, типизацию и разбор делать самим (на «Операциях» это ~10 полей фильтров); v8 требует Node 22.22+/React 19.2.7+ | `react-router` 8.5.0 (2026-10-19) | MIT |
| React Router framework mode / TanStack Start | Роутер + серверная часть (SSR, серверные функции) | Один проект «и фронт, и сервер» | Нам не нужно: бэкенд уже на Node отдельно; два сервера; серверные функции дублируют API | RR 8.5.0; `@tanstack/react-start` 1.169.4 (docs называют «stable») | MIT |

**Рекомендация: Vite 8 + TanStack Router (файловые маршруты) + TanStack Query.** Для localhost-приложения без SEO
серверный рендеринг — чистая стоимость. Решающий довод — типизированные параметры адреса: фильтры операций,
период дашборда и «контекст страницы для агента» (`CHAT-08`) превращаются в одну Zod-схему на маршрут. Защита
маршрутов (первый запуск `AUTH-10`, админка `ADM-*` только для админа) — через `beforeLoad` с редиректом.
Статика после `vite build` отдаётся бэкендом (тот же адрес — не нужны CORS и отдельные cookie-настройки), в разработке —
`server.proxy` Vite на бэкенд (SSE через прокси работает [С]). **Что изменит выбор:** если сопровождать будет тот, кто
уже знает React Router, — RR 8 в режиме данных вполне допустим и совместим с Vite 8 [С]; Mantine и всё остальное из
этого файла от роутера не зависит.

**Стыки.** Бэкенд (03): отдаёт статику и `/api/*`, тот же origin. Монорепо: `apps/web` не импортирует
код из `apps/api` — только из `packages/schemas` (dependency-cruiser это проверяет). Для NFR-24 (доступ по LAN) —
`server.host: true` в разработке включается флагом; на «боевом» запуске слушает бэкенд.

**Риски.** Vite 8 с Rolldown вышел 7 месяцев назад — достаточно свежий; `@vitejs/plugin-react` 6 больше не тянет Babel
(React Compiler подключается отдельно и помечен экспериментальным) [В из README]. React Compiler **не берём** в MVP.
**Вопрос пользователю:** нет (технический выбор), достаточно сообщить.

Источники: vite.dev/blog/announcing-vite8; reactrouter.com/changelog; tanstack.com/router/latest/docs/guide/search-params;
tanstack.com/start/latest/docs/framework/react/overview; `npm view` (версии).

**Рекомендация: Mantine 9.** Причины простыми словами:

1. Это единственный набор, где **всё нужное лежит готовым и бесплатным под одной темой**: даже диапазон дат
   (в MUI это платный Pro — нарушило бы `NFR-02`), календарь с событиями, командная палитра, `capture` для камеры
   телефона, уведомления с кнопкой.
2. Мало шаблонного кода: библиотека лежит в `node_modules`, а не копируется в репозиторий. У shadcn каждый
   добавленный компонент — ещё файл вашего кода (его потом «чинит» ИИ-агент и это растёт); у Mantine вы
   настраиваете тему один раз.
3. Тема из §7.1 ложится прямо на токены (`colorsTuple`) — проверено на прототипе.
4. У Mantine есть `llms.txt` и MCP-сервер `@mantine/mcp-server` (9.7.3, MIT) [В] — полезно, когда код пишут ИИ-агенты.

**Чего у Mantine нет и что придётся сделать самим:** набор для чата (пузыри, шаги, карточки — см. §6, у shadcn с лета
2026 это есть готовое: AI Elements, Trace, Message Scroller [В, changelog]); нижняя панель навигации с круглой кнопкой
«Сканировать чек» на телефоне (`DES-15`) — `AppShell.Footer` + своя кнопка; адаптация таблицы под телефон (карточный
список вместо таблицы) — `mantine-datatable` не адаптивна [Н]. Это объём в несколько компонентов, а не «рисовать всё».

**Подводные камни, найденные на прототипе [В]:**

- **Playfair Display по умолчанию рисует «старые» цифры** (`210` выглядит как маленькие `210`, «1» похожа на «I»).
  Для «ст. 210 НК» и цифр в заголовках нужен `font-variant-numeric: lining-nums` — проверил скриншотом, с ним
  цифры нормальные. Суммы и так в JetBrains Mono (`DES-07`).
- Подписи оси Y в `AreaChart` с форматом `1 234,56 BYN` обрезались слева — нужно задать ширину оси
  (`yAxisProps={{ width: … }}`) или короче формат.
- `defaultRadius` и вес `medium` в Mantine 9 поменялись (`md`, 600) — задать в теме явно.
- `light`-варианты в 9.x без прозрачности: «мягкие» тонированные фоны бейджей берём из явных токенов (`ivory`),
  не из автогенерации.

**Что могло бы изменить выбор.** (а) Макет окажется на Tailwind и пользователь захочет «пиксель в пиксель»
(тогда shadcn). (б) Если главным «вау» станет чат с богатыми блоками агента — shadcn с AI Elements ближе, но тогда
остальные 90% экранов (таблицы, формы, календарь, админка) собирать вручную. Мой расчёт: экранов с таблицами и формами
много, чат один (и боковая панель), поэтому выигрывает кит, закрывающий «остальное».

**Стыки.** `packages/schemas` (Zod) — общий с бэкендом; i18n (§7) — подписи Mantine-компонентов (`aria-label`, «ничего
не найдено») передаём через словарь. Тема живёт в одном файле `apps/web/src/theme.ts` и в CSS-переменных; тёмную тему
(`DES-01`) добавить позже — `cssVariablesResolver` умеет `light`/`dark` отдельно [В].

**Риски.** Mantine требует React ≥ 19.2 [В] — совпадает с выбором; major выходит раз в год с переименованиями
(9.0 переименовал `Collapse in→expanded`, `Grid gutter→gap` и т. д. [В]) — зафиксировать версию, обновлять осознанно.
`mantine-react-table` для Mantine 9 **не существует** (последняя стабильная 1.3.4 ждёт Mantine 6, бета 2.0 — Mantine 7) [В]
— не брать.

## 6. Чат со стримингом, шагами агента и карточками (`CHAT-02…05`, `CHAT-08`)

**Что решаем.** Как браузер получает ответ ассистента «по мере генерации», как показывать «Ищу траты за
сентябрь…», как рисовать **карточки** (чек, операция с «Отменить», расчёт вычета, чек-лист, мини-график, подтверждение
массового действия) и раскрываемые цитаты «ст. 210 НК». Пример: пока агент ищет траты, у пользователя виден шаг
«Ищу траты за сентябрь…»; затем появляется карточка расчёта вычета; в тексте «ст. 210 НК» раскрывается в дословную цитату.

### 6.1 Что протянуть между бэкендом и браузером (формат потока)

Решение важнее выбора библиотеки: **формат потока должен быть открытым и не привязанным к агентному фреймворку**,
потому что фреймворк агента (LangGraph / AI SDK / Deep Agents) выбирают в соседней области. Лучший кандидат —
**«UI message stream» из AI SDK**: это SSE-поток с JSON-событиями (`text-delta`, `reasoning-*`, `tool-input-*`,
`tool-output-available`, `data-*`, `start-step/finish-step`, запрос подтверждения инструмента, `error`), заголовок
`x-vercel-ai-ui-message-stream: v1`; в документации прямо сказано, что бэкенд может быть на любом языке [В].

**Проверено мной [В]:** написал сервер на голом `node:http` (без AI SDK) — он отдаёт эти события вручную; клиент —
`useChat` из `@ai-sdk/react` 4.0.156 (с `ai` 7.0.152). Результат в Playwright: вызов инструмента появился частью
`tool-searchTransactions` со состоянием `output-available` и результатом; два события `data-receipt` с одним `id`
(«Читаю чек…» → «Сумма сходится 100%») **слились в одну карточку** (обновление на месте); «временная» часть
`data-status` пришла только в колбэк `onData` и не попала в сообщение; текст докатился по словам. Вывод: формат можно
отдавать из любого бэкенда, а карточки — это `data-*` части или результаты инструментов.

Что требую от соседней области (агент): события потока — по таблице выше; **шаги** (`CHAT-02`) — как части
`tool-*` с аргументами (текст «Ищу траты за {период}…» собирает **фронт** по имени инструмента и его аргументам
из словаря i18n; это дешевле, чем просить модель писать статусы, и тексты управляются переводом); **карточки** —
как типизированный вывод инструментов (`tool-calcDeduction` → `DeductionCard`) либо `data-*` с `id`, если карточка
обновляется (чек: «Читаю…» → «Проверяю арифметику…» → «Перепроверка строки 2…» → итог; `RCPT-02`, `RCPT-06`).

### 6.4 Как это рисовать (набросок)

- **Реестр карточек:** `{ toolName | dataType → React-компонент }`. Неизвестная часть → безопасный запасной вид
  («Не удалось показать блок»), текст ответа остаётся.
- **Шаги:** сворачиваемый список «Что я сделал» над ответом (иконка, текст, галочка/спиннер), пока `status === 'streaming'`.
- **Кнопки «Отменить»/«Изменить»/«Да»:** вызывают обычное API (то же, что на странице «Операции»), затем
  `invalidateQueries(['transactions'])` — таблица и дашборд обновляются сами; для массового действия — карточка
  подтверждения (`AGT-07`), без «Да» ничего не пишется.
- **Цитаты (`CHAT-05`):** агент присылает цитату частью `data-citation` (`id`, акт, статья, **дословный текст**,
  дата редакции, ссылка на pravo.by), а в тексте стоит маркер ссылки; клиент превращает маркер в «чип» «ст. 210 НК»,
  по нажатию — `Popover` (компьютер) или нижняя шторка (`Drawer`, телефон) с текстом цитаты Playfair и полосой `coral`
  (`DES-12`). Формат маркера и проверку дословности (`LAW`) определяют соседние области — с моей стороны нужен
  стабильный идентификатор цитаты.
- **Markdown в ответе:** `react-markdown` 10.1.0 (последний релиз 2025-03 — API стабилен) + `remark-gfm`; нужна лишь малая часть
  разметки (жирный, списки, ссылки). Мерцание незакрытых `**` во время стрима, если будет мешать, лечится пакетом
  `remend` (1.4.0, Apache-2.0, даёт Streamdown) [С, отдельно от Streamdown не пробовал]; Streamdown 2.7.1 целиком
  тянет Tailwind-ориентированные зависимости — не нужен.
- **Автопрокрутка к концу:** `use-stick-to-bottom` 1.1.6 (MIT) — «липнет» к низу, пока пользователь не прокрутил
  вверх (как в AI Elements) [С], либо 20 строк своего хука.
- **Контекст страницы (`CHAT-08`):** хук `usePageContext()` собирает маршрут, параметры адреса (период, фильтры),
  выбранные строки; уходит в теле запроса `prepareSendMessagesRequest` и проверяется общей Zod-схемой на бэкенде.
  Плавающая кнопка (`Affix`) открывает `Drawer` справа; на телефоне — полноэкранный маршрут чата.
- **Вложения (`CHAT-03`):** кнопка → тот же `POST /receipts`, что и «Сканировать чек»; результат приходит карточкой.
  Фоновые задачи (распознавание, импорт) **не должны зависеть от открытого чата** → нужен отдельный
  **канал событий** `GET /api/events` (SSE, нативный `EventSource`, тот же origin, куки) — прогресс чека/импорта,
  уведомления, «закончился импорт» → `invalidateQueries`. Это же закрывает `NFR-21` («долгие операции идут в фоне
  с видимым прогрессом»).
- **Возобновление:** `useChat({ resume: true, id })` продолжает поток после перезагрузки страницы или смены
  экрана — потребует от бэкенда хранить активный поток (стык с областью агента).

**Что могло бы изменить выбор.** Если пользователь захочет ветвление ответов («редактировать сообщение и
перегенерировать») и голос/вложения как у ChatGPT «из коробки» — assistant-ui сэкономит код; но он 0.x, и придётся
оборачивать в нашу тему. Если выберут LangGraph Agent Server (отдельный сервер, не наш Node) — `@langchain/react`
станет естественным; но это отдельный сервис в Docker, чего задание не предполагает.

**Риски.** Формат потока AI SDK — стандарт де-факто, но принадлежит Vercel; смягчение — он открытый и мы его
реализуем адаптером (≈ один модуль), фронт зависит только от `useChat`. Мажорные обновления `ai` частые (v7 уже в
октябре 2026) — закрепить версии. **Вопросы пользователю:** нужна ли правка/перегенерация сообщений и ветки
диалога (в SPEC нет — по умолчанию нет).

## 7. Данные, формы, i18n, форматы

### 7.1 Данные с сервера — TanStack Query

**Что решаем.** Как браузер кэширует списки и обновляет их после действий (в том числе сделанных агентом).
Пример: агент записал «Кафе — 15 BYN», и таблица «Операции» и дашборд сами обновились.

**Рекомендация: TanStack Query 5.104.5 (MIT)** — стандарт де-факто, дружит с TanStack Router (`ensureQueryData` в
загрузчиках маршрутов). Ключи запросов — фабрики по сущностям; инвалидация — по сигналу «инструмент записи завершён»
(`tool-*` с записью) или события из канала §6. «Отменить» (`P5`) — не оптимистичное удаление, а вызов
`POST /…/undo` с токеном отмены, который вернул сервер; сообщение `Notifications` с кнопкой. Локальное состояние
(Zustand 5.0.16, MIT) — только для UI-мелочей (открыта ли панель чата); состояние страницы — в адресе (§1).
Типизированный клиент API — зависит от бэкенда (03): либо клиент из общих Zod-схем (`packages/schemas`), либо
автогенерация (tRPC/oRPC/Hono RPC) — формат контракта выберет область бэкенда.

### 7.2 Формы

| Вариант | Суть | Плюсы | Минусы | Версия [В] |
|---|---|---|---|---|
| **Mantine Form** | Форма из `@mantine/form`, валидация `schemaResolver(zodSchema)` (стандарт Standard Schema) | Нет отдельных пакетов; те же Zod-схемы, что на бэкенде; `getInputProps` связывает поля Mantine одной строкой | Привязан к Mantine (для нас плюс) | 9.7.3 |
| React Hook Form + `@hookform/resolvers` | Самая распространённая | Огромная экосистема | Ещё одна зависимость + адаптеры к каждому полю Mantine | 7.91.0 / 6.0.0 |
| TanStack Form | Типобезопасная, Standard Schema | Хорошая типизация | Меньше готовых связок с Mantine | 1.33.5 |

**Рекомендация: Mantine Form + Zod 4.6.7.** Проверил тестом [В]: форма с `NumberInput` + `schemaResolver(zod, {sync:true})`
в Vitest 5 + Testing Library показала ошибку «Сумма должна быть больше нуля» из Zod-схемы (тест проходит за ~2 с).
Например, при добавлении нового поля в операцию вы меняете **одну** Zod-схему в `packages/schemas` — форма, проверка
на сервере и тип в таблице обновятся вместе. Сообщения ошибок схемы — ключами/функциями i18n, а не строками внутри схемы
(схемы общие с бэкендом, который тоже должен быть i18n-ready).

### 7.3 Переводы (i18n, `NFR-19`)

**Что решаем.** Весь текст интерфейса — не в разметке, а в словаре, чтобы позже добавить беларусский/английский.
Нужны правильные множественные числа: «1 операция, 2 операции, 5 операций» (проверил `Intl.PluralRules('ru')`:
1→`one`, 2→`few`, 5→`many`, 21→`one` [В]).

| Вариант | Суть | Плюсы | Минусы | Версия [В] | Лицензия |
|---|---|---|---|---|---|
| **i18next + react-i18next** | Словарь по ключам (JSON), типизированные ключи | Самая распространённая; работает **и в браузере, и на Node** — те же словари для бота Telegram, уведомлений, писем; ключ с ошибкой = ошибка типов; множественные числа через `Intl.PluralRules` [С] | Нужно придумывать ключи; извлечение — отдельный инструмент | 26.5.8 / 17.1.6 (2026-10-24) | MIT |
| Lingui 6 | Текст пишется прямо в коде (`t`…``), извлекается в `.po` | Удобно писать и читать, нет ключей; нативный Rust-преобразователь макросов работает с `@vitejs/plugin-react` и Vite 8 без Babel (по документации) [В] | Макросам нужно преобразование на сборке — для Node-бэкенда (бот, письма) неудобно (tsx/esbuild макросы не выполняет) [Н]; меньше сообщество | 6.10.1 | MIT |
| Paraglide JS 2 | Компилирует сообщения в функции, дерево зависимостей чистое | Типобезопасно, малый размер | Меньше готовых связок с Mantine и бэкендом; менее распространён | 2.29.1 | MIT |

**Рекомендация: i18next** — главный довод общий словарь с бэкендом (`packages/i18n` для бота, push-уведомлений, писем).
**Что изменит:** если бот и письма будут шаблонами на стороне бэкенда отдельно — Lingui приятнее для интерфейса.
**Вопрос к области бэкенда/Telegram:** где живут тексты уведомлений (общий пакет или отдельно).

Форматы — **без библиотек, нативный `Intl`** [В, проверено на этой машине, Node 24]:
`new Intl.NumberFormat('ru-RU',{style:'currency',currency:'BYN'}).format(1234.56)` → `1 234,56 BYN` с неразрывным
пробелом U+00A0 между разрядами и перед `BYN` — **это ровно `DES-17`**; проценты `18,5 %`; даты
`Intl.DateTimeFormat('ru-RU',{timeZone:'Europe/Minsk'})` → `22.10.2026` (`NFR-23` — часовой пояс задаётся явно, а не берётся
из телефона). Оставить одну обёртку `formatMoney`/`formatDate` в `packages/shared`. Mantine Dates 9 хранит даты строками
`YYYY-MM-DD` [В] — поэтому смещения часовых поясов «на сутки» не возникает; русские названия месяцев — `import 'dayjs/locale/ru'`
+ `DatesProvider` [В] (либо `Intl`-форматтеры без dayjs-локалей). Белорусский язык интерфейса не нужен в MVP
(ассистент отвечает на русском), но `be` в `Intl.PluralRules` работает [В].

## 8. Голос в браузере (`VOICE-02`) и фото с камеры (`RCPT-01`)

**Голос.** `MediaRecorder` + `getUserMedia({audio:true})`; формат выбирать **проверкой**, не по угадыванию:
`['audio/webm;codecs=opus','audio/mp4','audio/ogg;codecs=opus'].find(MediaRecorder.isTypeSupported)`. Проверил в Google
Chrome 156 на этой машине [В]: поддерживаются `audio/webm;codecs=opus` (формат по умолчанию) и `audio/mp4`; `audio/ogg`
и `audio/wav` — нет. Safari исторически пишет только MP4/AAC [С из MDN-подобных источников, не проверял], Firefox — WebM/Ogg
Opus [С]. Облачное распознавание Groq принимает `flac, mp3, mp4, mpeg, mpga, m4a, ogg, wav, webm`, до 25 МБ на бесплатном
тарифе, сам приводит к 16 кГц моно [В] — запись голоса на несколько минут умещается; **локальная модель** (запасной путь,
`VOICE-03`) вероятнее всего ждёт WAV 16 кГц — значит бэкенд нормализует через ffmpeg [Н, вопрос 03]. Поток: кнопка микрофона →
запись (индикатор уровня через `AnalyserNode`, ограничение длительности) → `POST /api/voice/transcribe` (multipart) →
готовый текст **вставляется в поле ввода** с возможностью поправить (по `VOICE-02`). Микрофон есть только в защищённом
контексте: проверка `window.isSecureContext && navigator.mediaDevices` — иначе вместо кнопки подсказка «Надиктуйте в Telegram»
(`VOICE-02`; браузер по LAN-HTTP не даст `getUserMedia` — подтверждает R24). Отказ в доступе, занятый микрофон, пустая
запись — отдельные понятные сообщения (`DES-16`).

**Фото чека.** Обычный `<input type="file" accept="image/*" multiple>` (Mantine `FileButton`): на телефоне браузер
сам предложит «Камера / Галерея» (`RCPT-01`) и **не требует HTTPS** (это системный выбор файла, а не `getUserMedia`) [С];
атрибут `capture="environment"` у `FileButton` есть [В] и открывает сразу камеру — отдельной кнопкой «Снять», если
захочется. Перетаскивание на ПК — `Dropzone` (и на всю страницу — `Dropzone.FullScreen` [С]). Несколько фото — каждое
отдельным запросом, у каждого свой прогресс (канал событий §6). Загрузка с прогрессом байтов — `XMLHttpRequest`
(у `fetch` нет прогресса отправки); в нашем случае на LAN это редко важно. **HEIC с iPhone:** iOS при `accept="image/*"`
обычно сам отдаёт JPEG [Н], но бэкенд всё равно должен уметь HEIC и очень большие снимки (стык с 02/чеками: готовая
сборка `sharp` без HEIC [Н]); на клиенте ничего не пережимаем, кроме случая, когда бэкенд попросит уменьшить размер.
Облачная модель с картинками на Groq принимает до 3 изображений на запрос [В] — это ограничение бэкенда, не фронта.

Источники: developer.mozilla.org (`MediaRecorder.isTypeSupported`); console.groq.com/docs/speech-to-text, /docs/vision;
mantine.dev/core/file-button; тест — `scratchpad/research-frontend/proto/mr.mjs`.

## 10. Шрифты локально (`DES-05…09`)

**Решение:** `@fontsource-variable/inter`, `@fontsource-variable/playfair-display`, `@fontsource-variable/jetbrains-mono`
(5.3.0 каждый, лицензия OFL-1.1) — переменные шрифты npm-пакетами; в сборку Vite попадают файлы `woff2` по поднаборам
(`latin`, `cyrillic`, `cyrillic-ext` …), у всех трёх есть кириллица [В: файлы `*-cyrillic-*.woff2` появились в `dist/assets`
собранного прототипа]. Размеры кириллических поднаборов: Inter 18,7 КБ (+25,9 КБ расширенный), Playfair 21,2 КБ,
JetBrains Mono 12,1 КБ [В]; браузер загружает только нужные поднаборы по `unicode-range` [С]. Внешних CDN нет (`DES-09`).
Нюансы: имена семейств — `'Inter Variable'`, `'Playfair Display Variable'`, `'JetBrains Mono Variable'`; **для
Playfair включить `font-variant-numeric: lining-nums`** (иначе цифры «старого стиля», см. §2); курсив Playfair (если
понадобится в цитатах) — отдельный импорт `…-italic`. Альтернатива — скачать файлы вручную в репозиторий, но пакеты
проще обновлять и ничего не копируют в git. **Риск:** нет.

## 11. Структура фронтенда в монорепозитории и стыки

```
apps/web/            Vite + React: routes/ (TanStack Router), features/ (chat, receipts, operations, dashboard, calendar, admin),
                     components/ (карточки, обёртки), theme.ts, i18n/
packages/schemas/    Zod-схемы: DTO API, типы частей сообщений чата (data-* и tool-*), параметры адреса, page-context
packages/shared/     formatMoney/formatDate (Intl), константы
```

Границы для dependency-cruiser: `apps/web` → только `packages/*`; `features/*` не импортируют друг друга (общее —
в `components/`); `routes/` — тонкие, логика в `features/`. **Что требую от соседей:** бэкенд (03) — один origin, статика,
SSE-эндпоинты `/api/chat` (UI message stream) и `/api/events`, возобновляемые потоки; схемы — в `packages/schemas`;
агент (06) — типы частей сообщений и стабильные `id` у цитат/карточек; Telegram/уведомления — общий словарь i18n
или явное решение, что нет; тесты/QA — режим воспроизведения.
