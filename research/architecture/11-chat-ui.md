# 11 — Чат ассистента на Mantine: что делать, если готовых компонентов для ИИ нет

Дата ресерча: 2026-10-24. Метки уверенности: **[В]** проверил сам (запустил, измерил, прочитал первоисточник,
`npm view`, GitHub API), **[С]** косвенно (документация, README), **[Н]** предположение.

Вопрос пользователя: «В Mantine нет компонентов для ИИ-ассистента — всплывающее окно чата, вывод ответа по токенам,
привычные анимации. Нормально ли это, как решать, не перейти ли на другую библиотеку?»

## Коротко

1. **Это нормально, и переходить не нужно.** Готовых «ИИ-компонентов» нет ни у одной крупной библиотеки интерфейса
   (Mantine, MUI, Ant Design, Chakra): чат — это не кнопка и не таблица, а узор из обычных деталей. У shadcn/ui такие
   «узоры» появились только в октябре 2026 и **копируются в ваш код** (это не пакет). В списке пакетов Mantine
   (`carousel charts code-highlight core dates dropzone form hooks modals notifications schedule spotlight tiptap …`)
   чата нет, и это не упущение — [В: `gh api` по каталогу `packages/@mantine`].
2. **Всё нужное для чата в Mantine уже есть как «детали»**: `Drawer` (боковая панель), `Popover`/`Drawer` снизу
   (карточка цитаты), `Loader type="dots"` («печатает»), `Collapse` (шаги), `Textarea autosize`, `Progress`,
   `ActionIcon`, `VisuallyHidden`. Недостающее — три небольшие вещи: рендер потокового markdown, автопрокрутка и
   сами пузыри по макету. Первые два закрываются крошечными пакетами, третье — ~70 строк CSS из `kit.css`.
3. **Я собрал прототип этого варианта и проверил**: окно чата по макету «Пуща и янтарь», настоящий сервер AI SDK 7
   (с имитацией модели), потоковый markdown без мерцания, чип «ст. 210 НК» с цитатой, шаги агента, карточки, «Стоп»,
   автопрокрутка, `aria-live`. **Весь чат — ≈ 340 строк TSX + 67 строк CSS**; 25 автоматических проверок
   проходят (в т. ч. axe WCAG 2.2 AA — 0 нарушений) [В].
4. **Рекомендация: вариант (а)** — Mantine + `useChat` + свой тонкий рендер (react-markdown + `remend`) + свои
   компоненты по макету. Вариант (б) «Mantine + shadcn/AI Elements только для чата» технически работает
   (Tailwind с Mantine не конфликтует — проверил), но даёт вторую систему стилей ради ~2500 строк чужого кода,
   а сам AI Elements от Vercel **закрывается в конце ноября 2026** (переезжает в shadcn/ui). Вариант (в) — потерять
   графики, календарь и таблицу Mantine ради чата — не стоит.

## 1. Какие готовые наборы чата есть (на 2026-10-24) и подходят ли к Mantine

**Что решаем.** Взять ли готовый набор для чата или писать свои компоненты. Пример: «ответ ассистента печатается по
кусочкам, внутри `**жирные суммы**` и ссылка „ст. 210 НК“ — как всё это нарисовать, чтобы не мигало?»

Две разные задачи, которые обычно смешивают:

- **Рисовать потоковый markdown** (Streamdown, react-markdown + remend) — «как превратить недописанный текст
  `**183,00 BY` в красивую строку».
- **Каркас чата** (AI Elements, assistant-ui, CopilotKit, chatscope…) — окно, пузыри, поле ввода, автопрокрутка.

Что показал эксперимент (`bench.mjs`, `flicker.mjs` в прототипе) [В]:

- **Без починки хвоста** текст на экране мелькает как `…ушло **18` → `…ушло **183,0` — 14 кадров из 149 за один
  ответ. С `remend` — 0 таких кадров.
- **Streamdown без Tailwind** выглядит «сломанным» по умолчанию: «жирный» — это `<span class="font-semibold">`, у
  которого без Tailwind нет жирности; списки и таблицы теряют вид. С ~5 строками своего CSS по атрибутам
  `[data-streamdown=…]` и `controls={false}` становится приемлемым, но блоки кода и таблицы всё равно остаются
  «полуручными» (см. скриншоты `static-streamdown.png` / `static-own.png`). С Tailwind и `@source` — выглядит хорошо,
  но в серой палитре shadcn (её надо перекрашивать нашими токенами).
- **`animated` у Streamdown** оборачивает каждое слово в `<span>` — за один ответ браузер удалил/пересоздал 65
  элементов (в «своём» варианте — 0). Для коротких ответов это не страшно, но выигрыша для пользователя нет.
- **`remend` не идеален** [В, нашёл тестом]: «**жирный и *вложенный*» остаётся с незакрытым `**`; голый `**` в конце
  не убирает; недописанную ссылку превращает в `[…](streamdown:incomplete-link)`. Я закрыл это 8 строками
  (`healTail` + проверка нечётного `**` + показ такой ссылки простым текстом). Остался 1 кадр из 377 (одиночная `*`
  сразу после слова внутри открытого `**`) — на практике незаметно.

## 2. Варианты решения (сравнение честно)

**Что решаем.** Как собрать окно чата, чтобы оно совпадало с макетом `design/` и не тянуло лишнего. Пример: макет
показывает тёмный пузырь пользователя справа, светлый пузырь ассистента слева, внутри — карточка лимита с полоской
прогресса и кнопки «Отменить / Изменить», ниже — подсказки-«пилюли».

| | **(а) Mantine + `useChat` + свой рендер** | (б) Mantine для приложения + AI Elements/shadcn только для чата | (в) Целиком shadcn/ui |
|---|---|---|---|
| Суть | Свои ~10 компонентов на Mantine; markdown — react-markdown + remend; автопрокрутка — `use-stick-to-bottom` | Рядом ставим Tailwind 4 + shadcn; чат собираем из копируемых AI Elements | Весь интерфейс (таблицы, календарь, графики, формы) — на shadcn/ui |
| Сколько кода (измерено/оценено) | **≈ 340 строк TSX + 67 CSS** (прототип целиком) [В] | Код чата меньше, но **+ ~2500 строк скопированных компонентов** (message, conversation, prompt-input, reasoning, tool, sources) + их shadcn-основа (button, tooltip, command, dropdown-menu, hover-card, select, collapsible…) [В: реестр] + перекраска под токены [Н] | Чат — как в (б), а всё остальное (таблица с выбором строк, календарь событий, диапазон дат, командная палитра, загрузка файлов) собирать вручную — см. сравнение в `07-frontend.md` §2 [В] |
| Соответствие макету | **Точное**: значения `.bubble-u/.bubble-b/.lref/.lawq` из `kit.css` переносятся один к одному (макет написан на обычном CSS, а не на Tailwind) [В] | Нужно переписать вид в Tailwind-классы и подогнать серую тему shadcn под «Пущу и янтарь»; два набора фокусов, теней, диалогов | Как (б), но на всём приложении |
| Качество / доступность | Проверено: axe 0 нарушений, focus-trap, Esc, возврат фокуса, `aria-live` по вехам [В]; зона ответственности — наша | Radix/Base UI — хорошая база [С], но проверять нужно всё равно; AI Elements сменит дом (ноябрь 2026) | Хорошая база [С] |
| Риск | Мы сопровождаем свой чат; мелочи вроде «Esc закрывает всё» ловятся тестами (см. §3.4) | Две системы стилей; AI Elements → миграция на shadcn-версию; Tailwind-классы в двух местах | Потеря готового из Mantine, объём работы на «остальные 90% экранов» (вывод `07`) |

| Конфликт стилей | Нет | **Не обнаружен**: с Tailwind 4 (и «просто», и с `@layer`-схемой Mantine `styles.layer.css`) панель чата отличается от версии без Tailwind на **0 пикселей** (сравнил скриншоты) [В] — но проверял только панель чата, не все компоненты | — |

**Рекомендация: (а).** Причины простыми словами:

1. **Чат — одна панель, остальное приложение — таблицы, формы, календарь, графики.** Готовое из Mantine экономит
   недели на «остальном»; чат стоит ~340 строк. Менять кит ради чата — менять большое на малое.
2. **Макет уже написан обычным CSS.** Перенос в Mantine/CSS-модули буквально копирует значения; в Tailwind его пришлось бы
   «переводить».
3. **Готовых чат-наборов, которые не тянут Tailwind или чужой SDK, нет** — а те, что тянут, дают лишь упаковку.
4. **Закрываем риск из `07-frontend.md`** («проверить, на чём сверстан макет»): макет — обычный CSS с токенами
   (`tokens.css`, `kit.css`), не Tailwind [В]. Вывод `07` не пришлось менять — наоборот, подтвердился.

**Что могло бы изменить выбор.**
- Нужны ветки ответов, правка/перегенерация сообщения и вложения «как в ChatGPT» из коробки → добавить
  **headless-примитивы assistant-ui** поверх Mantine (стили свои), не отказываясь от Mantine. Но это 0.x и +174 КБ gzip.
- Понадобятся блоки кода с подсветкой, формулы, диаграммы в ответах (для финансового ассистента маловероятно) →
  тогда Streamdown *вместе с Tailwind* только внутри ответа или Shiki отдельно.
- Если когда-нибудь решат отказаться от графиков/календаря Mantine — пересмотреть (в).

**Стыки.** Агент (04): части сообщения `tool-<имя>` + `data-citation` с `id`; метка `[[F12.2]]` в тексте. Данные (03):
фрагменты закона для карточки цитаты. Дизайн: `design/tokens.css` подключается как есть. Тесты: добавить сценарии
из §3.4 в Playwright.

**Риски.** Свой чат — это наш код: покрыть тестами «мерцание», «Стоп», автопрокрутку, Esc (в прототипе уже есть
сценарии — их можно взять). `remend` 1.x — молодой, версию закрепить.

### 3.2 Мерцание потокового markdown [В]

Два независимых теста:

1. **Живой поток, кадр за кадром** (`flicker.mjs`, 149 кадров одного ответа): кадров с «сырой» разметкой —
   `naive` **14**, **свой (remend + блоки) 0**, Streamdown 2; уменьшений высоты (прыжков вверх) — 0 во всех.
2. **Все префиксы текста** (`bench.mjs`: 377 начал тестового ответа с заголовком, списками, цитатой, ссылкой, вложенным
   жирным/курсивом и меткой `[[F12.2]]`): с сырой разметкой — `naive` **111**, свой **1**, Streamdown **24–25**.
   Метка `[[…` в хвосте ни разу не «протекла» на экран (недописанную прячет `withCitationLinks`).

Детали, которые пришлось исправить (все — в коде прототипа): голый `**` в конце, «жирный с вложенным курсивом»,
недописанная ссылка из `remend`.

### 3.3 Доступность чата (`aria-live`) [В, кроме реального скринридера]

- Лента переписки — `role="log"` с **`aria-live="off"`** и `tabIndex=0` (прокручиваемая область доступна с клавиатуры).
  Если поставить `aria-live="polite"` прямо на ленту, скринридер будет «захлёбываться» при каждом кусочке (за ответ их
  ~85) — так делать **нельзя**.
- Вместо этого рядом — скрытая живая область `role="status" aria-live="polite" aria-atomic`, которая объявляет только
  вехи: «Ассистент думает…», «Ищу операции за октябрь 2026…» (каждый шаг), в конце — «Ответ ассистента: …» целиком.
  За весь ответ она меняется **5 раз** (мерил `MutationObserver`-ом), а не десятки.
- Кнопки: «Отправить» / «Остановить ответ» (разные `aria-label`), «Прикрепить файл», «К последним сообщениям»;
  чип — `<button>` с `aria-haspopup="dialog"` и `aria-expanded`; шаги — `<button aria-expanded>`.
- **axe-core (WCAG 2.0–2.2 A и AA): 0 нарушений** на открытой панели с ответом (1440 px) и на телефоне (390 px).
  Автоматика ловит лишь часть проблем; **с NVDA/VoiceOver я не проверял** — это нужно сделать руками перед защитой.
- `prefers-reduced-motion: reduce` — анимации появления и «каретка» отключаются (проверил в эмуляции).

### 3.4 Автоматические проверки (`e2e.mjs`, 25/25) [В]

Шаги агента показываются в нужной последовательности; итог в живой области; чип открывает цитату (Literata,
редакция, pravo.by); Esc закрывает сначала всплывашку, потом панель, фокус возвращается на плавающую кнопку; карточка
операции с «Отменить/Изменить»; автопрокрутка следует за текстом, не дёргает при прокрутке вверх, кнопка возвращает вниз;
«Стоп» останавливает рост текста, частичный ответ остаётся, диалог можно продолжить; на телефоне нет горизонтальной
прокрутки, цитата — нижняя шторка, Esc закрывает только её.

## 5. Риски и открытые вопросы

1. **Реальный скринридер не проверялся** (NVDA/VoiceOver): схема «лента молчит + отдельная живая область» — по
   рекомендациям, автоматический axe чист. Проверка — отдельным этапом, лучше до защиты. [Н]
2. **Реальная модель не использовалась**: кусочки мока — 2–7 символов; у Groq/Z.ai встречаются крупные порции и паузы.
   Логика рендера от размера порции не зависит, но стоит прогнать eval-записи через тот же `flicker.mjs`. [Н]
3. **Safari/Firefox, реальный телефон** не проверял (Chrome 156 на этой машине, эмуляция 390 px). [Н]
4. **`remend`/`marked` — внешние зависимости рендера**; если `remend` перестанет поддерживаться, замена — 40 строк
   (проверка «открытых» `** * ` ~~`). Версии закрепить. [С]
5. **Хранение частично сгенерированного ответа при «Стоп»** — решает бэкенд/агент (04, 03): нужен `onAbort`/`onFinish`,
   иначе при перезагрузке страницы оборванное сообщение не вернётся.
6. **Метки цитат**: фронт ждёт, что данные цитаты (`label`, `act`, `article`, `quote`, `edition`, `url`) придут **раньше**
   текста с меткой — в прототипе это результат инструмента `getLawFragment`. В боевой системе то же можно отдавать
   `data-citation` с `id`. Нужно согласовать с областью агента. (`CHAT-10` — «статья изменилась после ответа» —
   дополнительный флаг в той же части.)
7. **Mantine CSS целиком** (`styles.css`) — 39 КБ gzip; если важно, подключать по компонентам. Для localhost не важно. [В]
8. **Не вошло в прототип**: список диалогов (`CHAT-01`), голос (`CHAT-07`), вложения (`CHAT-03`), подтверждение
   массовых действий (`AGT-07`), чек-лист с галочками, мини-график. Они не требуют новых «чат-библиотек»:
   `FileButton`/`ActionIcon`/`Modal`/`Checkbox`/`BarChart`/`Sparkline` из Mantine + `useChat`. Карточка подтверждения —
   `Modal` или карточка в чате + `addToolApprovalResponse` (в AI SDK 7 есть).
9. **Вопрос пользователю (по умолчанию «нет»)**: нужны ли ветки диалога, правка/перегенерация сообщения и вложения «как у
   ChatGPT»? Если «да» — добавить assistant-ui (примитивы) поверх Mantine; иначе не нужно.
10. **Вопрос пользователю:** хочется ли покадровое «проявление слов» (как в некоторых чатах)? Дёшево сделать на CSS для
    последнего абзаца; по умолчанию — нет.
